# テスト設計成果物レビュー プローブ

このreferenceは、プロダクトリスク、テスト要求、テスト条件 / カバレッジ項目、詳細テストケースを反証レビューする場合だけ読みます。

工程固有の詳細ルールは各担当Skillを正本とします。

## プロダクトリスク / テスト分析

主に次を疑います。

- プロジェクトリスクをプロダクトリスク評価へ混ぜていないか
- リスクに仕様 / 変更 / 依存等の根拠があるか
- 根拠不足を理由に発生可能性を不当に低くしていないか
- リスクレベルが設計深度へつながっているか
- 低リスクを対象責務の無言削除理由にしていないか
- リスクや一般論から未定義の製品期待を創作していないか

リスクマトリクスや採点ルールの詳細は`test-analysis`を正本とします。

## テスト要求

主に次を疑います。

- 現在有効な仕様根拠へ追跡できる検証責務になっているか
- 上流記載の単なる言い換えになっていないか
- 対象内の仕様根拠 / プロダクトリスクがテスト要求または妥当な扱いへ閉じているか
- プロダクトリスクや実装から期待挙動を創作していないか
- 無関係な責務を過剰統合していないか
- 具体条件 / 手順へ早すぎる具体化をしていないか

粒度・分割・閉鎖の詳細は`test-requirement-design`を正本とします。

## テスト条件 / カバレッジ項目

主に次を疑います。

- テスト要求がテスト条件または妥当な扱いへ閉じているか
- 候補母集団を識別せず恣意的に候補を省略していないか
- 採用しない候補に根拠付きの扱いがあるか
- 技法名だけでカバレッジ基準を定義した扱いにしていないか
- カバレッジ項目の具体性が不足していないか
- プロダクトリスクや仮説から未定義の期待挙動を創作していないか
- テストケースの実行手順へ先回りしていないか

BVA / Pairwise / 状態遷移等の技法固有カバレッジルールは`test-condition-design`を正本とし、本referenceでは再定義しません。

## 詳細テストケース

主に次を疑います。

- ケース単体で開始者 / 開始状態、準備、操作、入力 / 選択、PASS条件を判断できるか
- カバレッジ項目 / 内包テスト条件がテストケースまたは妥当な扱いへ閉じているか
- 別ケースの実行結果へ暗黙依存していないか
- 期待結果が観測可能か
- PASS / FAIL判定に使う期待結果が現在有効な仕様根拠へ追跡できるか
- プロダクトリスク / 実装 / 既存テストケース / 一般慣習から未定義の期待結果の根拠を創作していないか
- 許可されていない観測手段を勝手に追加していないか
- 無関係な目的を1ケースへ過剰統合していないか
- 正式用語ではなくAI独自ラベルを作っていないか

詳細テストケースの具体性、ケース分離 / 統合、期待結果の根拠の具体化は`test-case-design`を正本とします。
