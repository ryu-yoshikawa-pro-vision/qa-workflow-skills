# 判定根拠
解析済みstrict JSONを機械処理する。`status`のenum / nullableは区別する。OpenAPI 3.0ではnullableがbase typeへnullを加えるが、enum制約は維持されるため、enumにないnullは有効値として扱わず、nullのinvalid candidateと理由を明示する。nullableを独立したtest data requirementへ再構成しない。`amount`の0〜99 range、`required`とrequest時`readOnly`除外、`credential`のwriteOnly、local Customer `$ref`を区別する。OpenAPI Reference Objectの`customer`にある`sibling type`をschema assertionとして適用しない。既存EP/BVA childへskeletonを渡し、meaning parameter不足をunresolvedに保つ。schema再実行結果の`derived.test_data_requirements`に実際に含まれるenum / range / required由来の要求を使い、別builderで再構成しない。`pattern`はruntime-v1 subset外のため`code` propertyだけをunsupportedとして残し、独立して評価できる他propertyを失わない。
