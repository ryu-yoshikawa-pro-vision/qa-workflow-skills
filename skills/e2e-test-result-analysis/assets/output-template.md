# E2Eテスト結果分析 出力テンプレート

## 分析対象・実行事実

必須6項目は項目名だけでなく、`値`と`参照`を必ず埋めます。取得不能な場合も空欄にせず、`未確認`、`確認不能`、`対象なし`等の明示状態と根拠を記録します。
入力にcleanup状態が明記されている場合は、その状態表現を値欄へ保持し、根拠 / 参照欄へ確認できる証拠と不足を記録します。異なる状態表現への言い換えで入力事実を置き換えません。

| 項目                                                | 値 | 参照 |
| --------------------------------------------------- | -- | ---- |
| E2E対象 / logical primary                           |    |      |
| E2E実装参照                                         |    |      |
| TC ID（存在時のみ）                                 |    |      |
| resolved primary TestCase / 実行結果参照            |    |      |
| Playwright status / outcome / expectedStatus        |    |      |
| run全体status / process exit code / run-level error |    |      |
| cleanup状態 / 残存副作用                            |    |      |

## 判定

判定対象がない場合でも最低1行を作り、`判定状態`には`判定可能`、`判定不能`、`未分析`、`確認不能`のいずれか一つを記録します。証拠待ちや原因未確定などの補足は別欄に書き、状態値を連結しません。原因を推測で確定しません。

| 対象参照 | 判定状態                                | 原因 | 再現性                            | 根拠 |
| -------- | --------------------------------------- | ---- | --------------------------------- | ---- |
|          | 判定可能 / 判定不能 / 未分析 / 確認不能 |      | 再現 / 再現せず / 断続的 / 未確認 |      |

## 不足証拠・追加実行要求

追加実行が不要でも最低1行を作り、`追加実行の必要性 = 不要`と明示します。必要性欄は許可値のいずれか1つだけにし、理由を括弧等で連結しません。必要 / ブロック中の場合だけ、証拠・仮説・範囲・担当を埋めます。

| 追加実行の必要性         | 取得したい証拠 | 検証する仮説 | 必要な実行範囲 | 実行担当                    |
| ------------------------ | -------------- | ------------ | -------------- | --------------------------- |
| 不要 / 必要 / ブロック中 |                |              |                | `e2e-test-execution` / なし |

## 修正routing・要再検証

`修正先Skill`には正規Skill IDだけを記録します（例: `e2e-test-execution`）。ID欄に理由や括弧書きを連結せず、`qa-workflow経由`等のrouting経路や説明は`理由`欄へ記録します。

| 判定 / 不足 | 修正先Skill | 対象 / 実行範囲 | 要再検証範囲 | 理由 |
| ----------- | ----------- | --------------- | ------------ | ---- |
|             |             |                 |              |      |
