# 判定根拠

- 入力は、実利用で入力分布が偏り、稀な組合せも障害原因になることを示している。この運用上の分布の偏りを根拠に、固定seedのRandom Testingを追加する合理性がある。
- 入力には運用プロファイルの具体値や発生率がない。Likelihoodは統計的確率ではなく、変更の複雑性や稀な組合せでの障害という代理指標から定性的に判断し、判断信頼度が低いことを根拠に残す（`skills/test-analysis/references/guidance.md`のLikelihood基準）。発生率などの定量データは要求せず、創作もしない。
- ランダム生成だけで仕様境界のCoverageが完了したとは扱わず、決定論的な境界確認を併用する。
- 生成ケースの具体値と完了件数は後工程で確定する。
