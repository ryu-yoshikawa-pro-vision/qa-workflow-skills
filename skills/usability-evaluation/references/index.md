# UI / UX Evaluation References

Use only the references that match the target and evaluation question.

## Route by concern

- [UI patterns](patterns/index.md): purpose, applicability, interaction, state, and flow. Start here when the target is a recognizable interaction pattern.
- [Accessibility](accessibility/index.md): normative Web requirements, author conformance, and informative accessibility guidance.
- [Usability heuristics](heuristics.md): advisory prompts for control, feedback, and recovery.
- [Platforms and adopted Design Systems](platforms/index.md): use only when the target platform or project adoption matches.

The source inventory and capability status live in [source-catalog.md](source-catalog.md) and [source-coverage.md](source-coverage.md). These files record provenance and coverage; they are not a substitute for the relevant normalized reference entry.

## Evaluation contracts

- [Evaluation method](evaluation-method.md) defines scope, applicability, evidence, and result handling.
- [Evidence and Authority](evidence-and-authority.md) defines how to keep observed facts, project requirements, public standards, guidance, and heuristics separate.

Do not infer a product conformance claim from this corpus. Formal WCAG-EM evaluation belongs to `wcag-conformance-evaluation`.
