# Reference index

## Orientation and Navigation
<!-- reference-entry-id: REF-0020 -->

### Match navigation to structure
Check the information architecture, current location, routes to parent/sibling content, and whether a control represents hierarchy or a sequence. A breadcrumb can show hierarchy; it is not automatically appropriate for ordered steps. Side navigation can expose a section hierarchy, while overlapping or deep navigation can add complexity.

### Evaluate from the task
Use the supplied goal and page context to assess destination labels. DOM/accessibility and keyboard evidence support operation and navigation semantics; screenshots support visible hierarchy and responsive layout. USWDS guidance is advisory unless adopted.

## Search and Results
<!-- reference-entry-id: REF-0021 -->

### Search task
Assess whether search supports the supplied task and has a visible or programmatic label, submit action, and useful result context. Inspect retained query context, result titles, distinguishing metadata, and a route to a broader index when the set is incomplete.

### Collections and pagination
A compact collection may group related items with metadata; a larger archive may need a separate index or search. Pagination describes page-size splitting, not semantically meaningful groupings or steps. Preserve whether a set is bounded, the current page, and routes to adjacent/last pages.

### Advisory source boundary
USWDS guidance is advisory unless adopted. WCAG criteria are assessed separately and are not established by copying a Design System example.
