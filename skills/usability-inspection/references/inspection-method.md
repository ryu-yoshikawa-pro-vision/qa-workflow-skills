# Inspection Method

Use the generated scope rows as the closure inventory. General mode creates all seven fixed aspects; scoped mode creates only canonical requested aspects; formal-handoff mode observes only the typed requested scope.

For a live page, first establish current document and environment identity. Discover controls visually and through user-facing content before resolving an exact Playwright locator. Record state transitions, focus, feedback, and screenshots as separate evidence. Do not infer a semantic state from a screenshot or a visible appearance from an accessibility snapshot.

Responsive conditions are read from the browser's current style/condition evidence. Confirm executable numeric size transitions at before, transition, and after states. Keep style and scroll-state changes as nonnumeric variations. Incomplete inventory, unreadable source, and unsupported browser capability remain explicit.

The inspection may measure navigation timing, paint timing, and user-facing interaction timing only with a single clock domain. Keep pre-action actionability waiting separate from post-input response. Use an existing, provenance-bearing field source for Core Web Vitals; otherwise mark them unavailable.

If learnability is explicitly in scope and a source defines the intended step sequence, an optional Cognitive Walkthrough may review goal, action recognition, action-effect association, and feedback per step. It is not a mandatory general-inspection phase and cannot invent the correct sequence.
