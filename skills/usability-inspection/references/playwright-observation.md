# Playwright Observation Boundary

The repository's current Playwright execution path owns browser I/O. The package runtime materializes fixed requests and normalizes returned values; it does not install or select a new browser framework.

Use exact role/name, label, visible text, current-session identity, or population-index resolvers only after user-facing discovery. Re-resolve the target in the active session before each element probe. Parent scope, document/session identity, population revision, match count, and freshness determine whether the target is usable.

## API selection and observation boundaries

Prefer existing behavior and package-owned probes first, then language and browser APIs, then installed libraries. Add a custom implementation only when those options cannot meet a stated contract. Keep deterministic project contracts such as target refs, currentness, schema checks, cleanup, and evidence lineage when using a standard API.

Use Playwright Locators for target resolution, `getByRole()` / `getByLabel()` for user-facing target lookup, `isVisible()` / state methods for the corresponding Locator facts, and `boundingBox()` for viewport-relative CSS geometry. `isVisible()` does not mean that an element is in the accessibility tree, actionable, or inside the viewport; in particular, Playwright considers an `opacity: 0` element visible. Check accessibility-tree inclusion separately. `ariaSnapshotJSON()` (available since Playwright v1.63) can provide a browser-computed projection for a specific Locator, but it is not a general structured inventory with stable target IDs. Use it only where the fixed probe can match one projected node to one exact Locator. The current repository does not pin a Playwright package; use the existing browser owner that exposes this API. If the active route does not expose it, the fixed probe returns a non-success result instead of parsing YAML or inventing a fallback. An empty name and a failed projection are different; if the projection fails or is ambiguous, return a non-success result instead of an empty value. See the official [Locator API](https://playwright.dev/docs/api/class-locator), [actionability and visibility](https://playwright.dev/docs/actionability), and [accessibility testing](https://playwright.dev/docs/accessibility-testing) documentation for the API boundaries.

Playwright CSS Locators pierce open Shadow DOM. Fixed probe refs include each host/root boundary so equal local selectors in different hosts remain distinct. Do not add a shadow-root crawler. Closed Shadow DOM is not exposed to Locator traversal; frame contents are separate scopes and are not silently added to the current page population. When an in-scope result depends on such an unobservable population, keep it incomplete rather than reporting an empty complete set. Use Locator state such as `isEnabled()` where it expresses the required browser interaction state; retain browser DOM properties or ARIA attributes only for facts without a corresponding Locator API. Keyboard order comes from actual serial `page.keyboard` operations and the focused Locator, not a DOM count of presumed focusable nodes; record loop versus observation-limit outcomes and restore focus and scroll before returning.

Use browser APIs such as `getComputedStyle()`, `Range`, and `TreeWalker` only for facts Locators do not expose, such as text-node ranges or computed style values. Those focused uses must retain the same explicit root and target scope; they are not permission to build a generic DOM crawler or accessible-name engine. Preserve computed CSS facts for geometry or appearance when they are the required measurement, but do not call them accessibility-tree facts.

Persist only strings needed for the declared semantic evaluation. Prefer a boolean or finite property when that satisfies the contract, and never persist an entire accessibility snapshot, DOM tree, input value, raw URL, or secret as incidental metadata. Existing text-pattern redaction is only a heuristic and cannot identify arbitrary names, addresses, or secret strings. If a required raw string cannot be stored in an approved safe destination, retain its evidence ref, the fact that content was withheld, and the reason; do not claim the string was safely redacted.

Perform visual discovery without an implicit locator click that scrolls an offscreen element into view. When necessary, scroll explicitly through the user-facing page, save before/after evidence, and keep automation-targeted scrolling out of discoverability evidence. Actionability wait is evidence about the automation path, not elapsed user response time.

The fixed observation catalog has exactly seventeen canonical fields and one probe owner per field. `document.location` returns only a redacted scheme marker; its envelope carries an opaque `hmac-sha256:<hex>` identity computed inside the page from the complete current location with a non-extractable per-document key. Raw URL and key stay in page memory, so path, query, and fragment changes remain distinguishable without persisting URL components. The independent `document.title` probe returns fixed boolean predicates for HTML applicability, title-element presence, first-title child-node type, and non-whitespace title text; it never stores raw title text or a general DOM tree. ACT Rule 2779a5 uses this field. Formal WCAG machine probes use a separate typed finite catalog and the same in-memory document-identity key; the semantic observation field vocabulary does not expose formal probe selection.

HMAC identity generation depends on the browser's WebCrypto `SubtleCrypto` API, which is restricted to secure contexts. Use HTTPS or a browser-recognized trustworthy local origin such as `http://localhost` or `http://127.0.0.1`; ordinary HTTP origins generally cannot use it. The fixed probes check that the API exists and catch failures from the actual HMAC key/sign operation. If identity cannot be generated, they return an unavailable/blocked limitation without a raw-URL or unkeyed-hash fallback, and identity-dependent observations do not complete. A reload creates a new per-document key, so reacquire identity instead of reusing the prior document's token. A formal request is not materialized without an opaque identity; if WebCrypto becomes unavailable after a typed request exists, the fixed result remains blocked with no current-document identity or observation value.

`responsive-conditions` evaluates `@media` through `window.matchMedia()`. It inventories `@container` rules but records a null current match and `not-executable`, because CSSOM does not expose a standard API for the active container-query match state. Declaration/computed-style string equality is not evidence of a condition match. `responsive-boundaries` uses binary search only for a single simple `min-width`, `max-width`, `min-height`, or `max-height` media feature, whose match state is monotonic on the searched viewport axis. Range, exact-width, compound, comma-branch, and other media expressions remain `incomplete` with a reason instead of being called `no-numeric-transition` from a few sample points. The collector skips unexecutable container conditions, preserves independently evaluable media-query results, and restores the original viewport.

## Fixed page evaluation

`navigation-timing` and `paint-timing` use the same package-owned fixed dispatch. Navigation Timing returns only allowlisted numeric fields and omits the entry URL; Paint Timing returns only First Contentful Paint.

The `document.location`, `document.title`, `responsive-conditions`, `responsive-boundaries`, and `interaction-timing` catalog rows use the package-owned `scripts/fixed_browser_probes.js` function for their fixed page evaluation. The Playwright CLI loads this exact file with `run-code --filename`; do not copy its logic into an inline command. The browser owner passes only the materialized typed request through the temporary `window.__usabilityInspectionFixedProbeRequest` slot, then invokes the fixed file. The file consumes and removes that slot before dispatching a finite probe key. The transport call only assigns request data; it must not read or calculate browser observations. A readable condition inventory may be complete while a particular condition remains `not-executable`; that condition does not count as an evaluated responsive variation.

Every formal machine key in `assets/wcag-machine-probe-catalog.json` uses the separate fixed `scripts/fixed_wcag_machine_probes.js` dispatcher. Pass the exact typed request through `window.__usabilityInspectionFixedWcagProbeRequest`, then load the package file with `playwright-cli run-code --filename`. The dispatcher records bounded, allowlisted observations; it returns `incomplete` when the typed request does not identify the exact target, action, flow, or page set needed to act safely. Resize Text may operate only the uniquely named, visible, enabled `Text size` range control using real keyboard input. It records finite baseline/intermediate/target states, rendered text metrics and loss evidence without storing text content, then restores the control baseline. Text Spacing uses the fixed WCAG-required override and removes it before returning. A detected gradient/image/blend background, complex focus styling, or unreadable canvas text returns the catalogued machine limitation for formal manual routing. Do not provide selectors, substitute viewport/DPR/CSS changes for text scaling, or copy observation logic into an inline command. Run the production inspection runtime normalizer on the returned result before handing it to the formal owner.

Responsive boundary collection may change the viewport through `page.setViewportSize` and restores the original viewport in a `finally` block. It does not edit DOM or stylesheet state. Interaction timing requires a current exact resolver, one fixed Playwright action, one catalogued end predicate, a timeout, and a saved evidence reference. A package-owned `MutationObserver` and animation-frame check observe the end predicate; the event start and predicate detection use the same page `performance.now()` clock. The helper does not persist action values or predicate text.
