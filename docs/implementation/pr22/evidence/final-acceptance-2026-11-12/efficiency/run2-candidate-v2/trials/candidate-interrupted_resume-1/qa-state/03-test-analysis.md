### リスク → 設計深度

- 高（RISK-001, 002, 003, 005, 006）: 選択技法のカバレッジ基準を満たす。境界・状態・権限・エラー復旧を積極的に検討する。カバレッジ削減は理由を残す
- 中（RISK-004, 007, 008）: 基本カバレッジを満たす。組合せ・追加観点は根拠がある場合だけ加える
- 低（RISK-009）: 主挙動を代表するカバレッジを確保する。一般的なエッジケースを機械的に追加しない。ただしRISK-009はTR-011 / TR-016へ接続して閉じる

## 5. 選択テスト技法

| テスト技法 | 適用領域                                                         | 選択理由                                   | 関連プロダクトリスク / 仕様根拠   | `test-condition-design`への着眼点                      |
| ---------- | ---------------------------------------------------------------- | ------------------------------------------ | --------------------------------- | ------------------------------------------------------ |
| 境界値分析 | 数量上限 `L = min(在庫数, 購入上限数, 99)`                       | 単一の境界が最小値で決まる scalar 境界     | RISK-001, BR-CART-001             | `L-1 / L / L+1` と、3つの上限のどれがLを決めるか       |
| 同値分割   | 利用主体（guest / 顧客（有効） / 停止・退会 / operator / admin） | 主体ごとに利用可否が閉じた同値クラスになる | RISK-006, SPEC-CART-007           | 各主体の代表値と、停止・退会は「セッションなし」の扱い |
| 決定表     | 統合の除外判定、問題明細の判定、在庫減少時の挙動                 | 複数条件の組合せで結果が決まる             | RISK-002, RISK-003                | 条件は独立に保つ。未確定のルールはブロック中として残す |
| 状態遷移   | カート状態 active → consumed / abandoned、統合元の遷移           | 終端からの変更不可が仕様で明示されている   | RISK-003, RISK-009, SPEC-CART-008 | 有効遷移と、終端からの変更拒否                         |
| エラー推測 | 更新処理中の二重実行                                             | UI規約に防止の明示があり、根拠がある       | RISK-004, SPEC-CART-004           | 観測可能な結果は仮定（A-02）が承認されるまで保留       |

不採用: 組合せテスト（pairwise）は、要因が少なく決定表で網羅できるため採用しない。ランダムテスト・メタモルフィックテストは、明示された入出力関係がないため採用しない。
