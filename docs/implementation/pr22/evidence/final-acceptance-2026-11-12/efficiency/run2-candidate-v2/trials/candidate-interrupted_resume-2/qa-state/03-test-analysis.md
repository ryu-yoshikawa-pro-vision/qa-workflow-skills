# テスト分析: カート（`test-analysis`）

## テスト分析範囲

- 対象機能 / 変更: カート（追加、数量変更、削除、表示時の再検証、チェックアウト開始前の再検証、ログイン時のゲストカート統合）
- 案件固有のテスト目的 / 重点: 購入数量の正しさ、問題明細・価格未承認の状態でのチェックアウト阻止、統合結果の正しさと理由表示
- テストレベル: システムテスト（既定。ユーザー・案件・既存の割当での別指定なし）。版・統合の内部状態はUIからの観測に限界があるため、必要な観測は後述の観測方法で扱う
- 環境制約: 対象は`web-desktop`と`android`（画面状態表どおり）。製品commit `2a8bcf57`は未照合
- 対象外: 注文作成・注文確認時の再検証（`checkout-and-payment.md`が所有）、在庫減算（注文時）、商品管理
- ブロッカー: 局所のみ（Q-002、Q-003、Q-004、Q-005。詳細は`02-question-analysis.md`）
- 対象 / 実行範囲: テスト分析

## 採点方式の扱い

- 案件固有のリスク評価方式（Project Context）は未検出。標準の「影響度 × 発生可能性」マトリクスを使用する（`00-workflow-state.md`の既存判断を継承）
- マトリクス: 影響度 高×発生可能性 中以上 → 高、影響度 中×発生可能性 中 → 中、その他 → 低
- 判断信頼度: 中。根拠は仕様（`features/cart.md`、`state-and-scenarios.md`、`roles-and-permissions.md`、`storefront.md`、`decision_log.md` D-010）に限定。実装・過去の欠陥・アクセス履歴は未確認

## 選択したテスト技法

| テスト技法         | 適用領域                                                                                                    | 選択理由                                   | 関連プロダクトリスク / 現在有効な仕様根拠                | `test-condition-design`への着眼点                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------ | -------------------------------------------------------- | -------------------------------------------------------------- |
| 境界値分析         | 数量上限（min(在庫数, 購入上限数, 99)）、同一SKU合算後の数量                                                | 判定が閾値で切り替わる                     | RISK-01、SPEC-002                                        | 上限の各構成要素が最小となる3ケース、上限値・上限+1・上限-1・0 |
| 同値分割           | 権限、追加入口、統合の除外理由、表示時の問題種別、画面状態                                                  | 同じ結果になる入力のまとまりが明確         | RISK-03、RISK-04、RISK-06、SPEC-010、SPEC-011            | 除外理由ごとの代表値。許容上限超過は保留                       |
| デシジョンテーブル | チェックアウト開始の阻止条件                                                                                | 問題明細と価格未承認の組合せで結果が決まる | RISK-02、AC-CART-003、SPEC-009                           | 問題明細あり/なし × 価格未承認あり/なし                        |
| 状態遷移           | カート明細（empty、valid、invalid）、ゲストカート（有効 → abandoned）、価格（改定なし → 未承認 → 承認済み） | 状態と遷移の規則が仕様に明記されている     | RISK-02、RISK-03、SPEC-002、SPEC-003、SPEC-004、SPEC-008 | 有効遷移と無効遷移（拒否）の両方                               |

技法は問題構造に合うものだけを選んだ。組合せ（ペアワイズ）は、因子が少なく全組合せが小さいため今回は採用しない。
