- 非正式文書（SRC-007 / SRC-008）は cart の核心ルール（BR-CART-001〜003）と矛盾しない一方、版・追加操作・表示順などの詳細を追加している。これらは **SPEC へ昇格させず** INF として保持する。権威の所在は question-analysis（Q-06）で承認を求める。

## 5. 状態 / 遷移（SPEC-CART-008 由来）

| 現在状態             | イベント     | 条件           | 次状態                       |
| -------------------- | ------------ | -------------- | ---------------------------- |
| active               | 注文作成完了 | —              | consumed（注文機能側が起点） |

| consumed / abandoned | 任意の変更   | —              | 不可（終端）                 |

## 6. 制約 / 明示的境界

- 数量上限 = min(在庫数, 購入上限数, 99)（SPEC-CART-001）
- 統合の上限 = 同じ上限（SPEC-CART-002 の「許容上限」を BR-CART-001 と同一と解釈。解釈が異なる場合は UNK 扱い → 本書では同一と仮定せず、Q-03 に含めて確認対象とする）
- 権限: ゲスト・顧客（有効）のみ利用（SPEC-CART-007）

## 7. 後続Skillへの補足

- test-analysis: 数量上限は境界値分析の主対象。再検証と統合は決定表・同値分割の対象。
- test-requirement-design: 関連AC IDは direct mode のため `-` として、根拠は SPEC 行へ直接リンクする。
- test-condition-design: 期待結果は SPEC と解決済み UNK の範囲のみ使用。UNK に依存する CI は blocked と明示する。
