- 対象 / 実行範囲: テスト分析
- テストレベル既定: システムテスト（Webの画面操作で観測）。例外は下記「テストレベル判断」

## 2. プロダクトリスク

評価: 影響度（金銭・データ整合性・操作不能）× 発生可能性（ルールの複雑さ・状態の多さ）。最終レベルは影響度を優先した判断。

| リスクID     | 製品上のリスク / 失敗                                                                          | 関連仕様根拠                    | 影響度 | 発生可能性 | レベル | 根拠                                                                    | 判断信頼度 / 備考       |
| ------------ | ---------------------------------------------------------------------------------------------- | ------------------------------- | ------ | ---------- | ------ | ----------------------------------------------------------------------- | ----------------------- |
| RISK-CART-01 | 上限超過時に数量が自動補正される、または操作が部分適用される                                   | SPEC-CART-001/002               | 高     | 中         | **高** | 購入数量と価格の誤りに直結。境界が3種の最小値で決まる                   | 高                      |
| RISK-CART-02 | ゲストカート統合で数量・除外・理由表示が誤る（上限超過の取り込み、除外漏れ）                   | SPEC-CART-004/005               | 高     | 高         | **高** | 規則の組合せが多い（SKU合算・上限・4種の除外）                          | 高                      |
| RISK-CART-03 | 問題のある明細（価格変更・在庫切れ・非公開・ランク不足）が再検証されず、チェックアウトへ進める | SPEC-CART-007/008/009           | 高     | 中         | **高** | 注文の不成立・誤請求に直結。cart.mdとstate-and-scenariosの両方が要求    | 高                      |
| RISK-CART-04 | 統合元ゲストカートがabandonedにならず、二重統合される                                          | SPEC-CART-006、SPEC-CART-014    | 中     | 中         | **中** | データ整合性。ただし画面からは観測できない                              | 中（観測手段に制約）    |
| RISK-CART-05 | 更新操作の二重実行・並行更新で数量が二重加算される                                             | SPEC-CART-012、INF-CART-001/007 | 高     | 低〜中     | **中** | 影響は大きいが、UI抑止（SPEC）とサーバー整合性（INFERENCE）が二重に防ぐ | 中（期待結果がUNKNOWN） |
| RISK-CART-06 | operator / admin がカートを利用できる、または guest / customer が利用できない                  | SPEC-CART-010、FR-AU-009        | 中     | 低         | **中** | 権限違反の検出。ロール仕様は一部のみ確認                                | 中                      |
| RISK-CART-07 | 表示（現在価格・上限数・問題・合計・空状態）の誤り・欠落                                       | SPEC-CART-011/013               | 中     | 中         | **中** | 利用者の判断を誤らせるが、注文の誤りには直結しにくい                    | 中                      |
| RISK-CART-08 | 明細の表示順、再読込後の保持、ゲストIDの永続が誤る                                             | INF-CART-003/006                | 低〜中 | 低         | **低** | 承認待ち（P-01）のため、現時点では設計の深度を下げる                    | 低（根拠が未承認）      |

## 4. 選択したテスト技法

| テスト技法             | 適用領域                                                 | 選択理由                                   | 関連リスク / 仕様根拠            | `test-condition-design`への着眼点                                   |
| ---------------------- | -------------------------------------------------------- | ------------------------------------------ | -------------------------------- | ------------------------------------------------------------------- |
| 同値分割               | 数量入力（0 / 有効 / 超過）、利用者種別                  | 有効・無効・特別値（0）の区別が必要        | RISK-01, 06 / SPEC-001〜003, 010 | 0、1〜L、L超過の3クラス                                             |
| 境界値分析             | 数量の上限 L = min(在庫, 購入上限, 99)、合算値           | 境界で誤りが出やすい                       | RISK-01 / SPEC-001,002           | L-1, L, L+1、在庫・上限・99それぞれが最小になる値                   |
| デシジョンテーブル     | 統合の取り込み可否・除外理由、表示時の問題判定           | 条件の組合せで結果が変わる                 | RISK-02, 03 / SPEC-004,005,007   | 統合: 合算≤L/超過 × 公開 × ランク × SKU有効 × 在庫>0。表示時: 4要因 |
| 状態遷移               | カートの active→abandoned/consumed、チェックアウトゲート | 遷移の許可・禁止が仕様にある               | RISK-04, 03 / SPEC-006,009,014   | 終端からの変更不可、承認前のゲート                                  |
| 組合せ（ペアワイズ）   | 統合の除外理由の複数同時該当                             | 理由の組合せが多い。ただし表示規則が未確定 | RISK-02 / UNK-CART-004           | 複数理由の表示はP-05待ち。組合せ自体は2-wiseで設計                  |
| エラー推測             | 二重送信、複数タブ、並行更新                             | 仕様が少なく経験的な観点が有効             | RISK-05 / SPEC-012               | 期待結果はP-02待ち                                                  |
| CRUD（表示項目の網羅） | 明細の表示項目、空状態                                   | 表示項目が仕様で列挙されている             | RISK-07 / SPEC-011,013           | 項目ごとの存在確認                                                  |

| 要件 / 懸念                                   | 操作可能か                                                     | 観測可能か                                                       | 合否判定可能か                  | 選択テストレベル                                                 | 扱い / 備考                                                                          |
| --------------------------------------------- | -------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 数量変更・0削除・上限拒否（SPEC-001〜003）    | 可                                                             | 可（カート画面の数量・合計）                                     | 可                              | システムテスト                                                   | 拒否メッセージはP-04待ち。数量維持は判定可能                                         |
| 数量の境界（L-1, L, L+1, 99）                 | 可                                                             | 可                                                               | 可                              | システムテスト                                                   | 在庫・購入上限の値はSeedで指定（`cart-with-invalid-items` 等。境界用のSeedは未確認） |
| ゲストカート統合の結果（SKU合算・除外・表示） | 可（ログイン操作）                                             | 一部（統合結果の画面表示は可。内部 version は不可）              | 一部                            | システムテスト（結果表示）＋ Application Integration（内部状態） | P-08                                                                                 |
| 統合元ゲストカートの abandoned                | 間接的                                                         | **不可**（FR-TC-008: 観測APIはOrder / SKU在庫 / Review集計のみ） | 不可（E2E）                     | Application Integration                                          | `test_strategy.md` に沿う。P-08で承認                                                |

| 価格変更の承認ゲート                          | 可                                                             | 可                                                               | 一部（承認操作の仕様がUNKNOWN） | システムテスト                                                   | P-07                                                                                 |
| 二重実行防止                                  | 可（連続操作）                                                 | 一部                                                             | 不可（期待結果がUNKNOWN）       | システムテスト                                                   | P-02                                                                                 |
| 利用者種別の利用可否                          | 可（ロール別ログイン）                                         | 可                                                               | 可                              | システムテスト                                                   | 拒否表示はroute仕様（非正本）の確認が必要                                            |
