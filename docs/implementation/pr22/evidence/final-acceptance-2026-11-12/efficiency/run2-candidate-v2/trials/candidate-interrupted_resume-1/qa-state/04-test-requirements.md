## 3. 分割・統合の判断

- TR-001（上限の拒否・補正なし）と TR-002（0指定の削除）は、操作の結果が異なるため分割した
- TR-004（再検証）と TR-005（価格変更の承認）は、対象とする判定が異なるため分割した
- TR-006（問題明細の購入不可）と TR-007（ランク不足）は、再検証タイミングの判断が異なるため分割した
- TR-009（統合の結果）と TR-010（統合元の状態遷移）は、責務が異なるため分割した

## 4. 追跡性の確認

- 全TRは少なくとも1つの現在有効な仕様根拠へ戻る（TR-014 は要求化しないためブロック中として記録）
- 全SPEC / AC / BR / RISKは、TR、別機能への委譲、またはブロック中として閉じている
- 記載は「何を検証するか」に留める。組合せ、具体値、手順は含めない
