# 03 テスト分析（test-analysis）: カート

入力: `01-spec-analysis.md`（再利用）、`02-question-analysis.md`。
対象 / 実行範囲: テスト分析。

## テスト分析範囲

- 対象機能 / 変更: カート（追加・数量変更・削除、表示時・チェックアウト開始時の再検証、ログイン時のゲストカート統合）。カート画面 `SCREEN-STOREFRONT-CART`（状態 default / empty / invalid-items）。
- 対象ロール: ゲスト、有効な顧客（customer）。運用者・管理者はカート利用不可（SPEC-001）。
- 案件固有のテスト目的 / 重点: 数量上限と再検証による誤った購入・金額の防止、統合時の購入権限違反の防止。
- テストレベル: **システムテスト**（既定。ユーザー・案件コンテキスト・既存の有効成果物に別レベル指定なし）。
- 環境制約: 観測は画面（web-desktop / android）。統合後の `abandoned` 状態が UI に出ない可能性がある（観測手段は test-architecture-design で決定）。
- 対象外: チェックアウト・注文への変換（`checkout-and-payment.md`、`orders.md`）、商品詳細からの追加ボタンの活性可否（`storefront.md`）、ログイン処理そのもの（`authentication.md`）、`consumed` 状態（注文側）。
- ブロッカー: `02-question-analysis.md` のとおり。影響は TR 単位。
- 案件固有リスク評価方式: **未確認**（案件コンテキストに記録が無い）。このため `references/guidance.md` の標準リスクマトリクス（影響度・発生可能性 各1〜4）を使う。

## プロダクトリスク一覧

## 選択したテスト技法

| テスト技法         | 適用領域                                                                              | 選択理由                                           | 関連プロダクトリスク / 現在有効な仕様根拠  | `test-condition-design`への着眼点               |
| ------------------ | ------------------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------ | ----------------------------------------------- |
| 境界値分析         | 数量の上限（min(在庫数, 購入上限数, 99)）の上限ちょうど・上限+1・0                    | 単一のスカラー境界。SPEC-002 が境界を明示          | RISK-001、SR-CART-01                       | 上限を決める3値それぞれが最小になる場合を分ける |
| 同値分割           | 数量の代表値（正常・上限超過・0）、ロール、画面状態                                   | 有効・無効の区分が明確                             | RISK-001、RISK-007、SR-CART-04             | 代表値を一つ選ぶ。不正入力（TR-004）は除外      |
| デシジョンテーブル | 統合規則（ゲスト明細×会員明細×除外理由）、再検証（公開・権限・在庫・ランク×トリガー） | 条件の組合せで結果が変わる                         | RISK-003、RISK-005、SR-CART-02、SR-CART-03 | 除外理由は1明細1理由（TR-025 はブロック中）     |
| 状態遷移           | ゲストカートの active → abandoned、終端状態からの変更拒否                             | 状態と遷移禁止が仕様で明示                         | RISK-004、SR-ST-01                         | 遷移元と遷移禁止の組を網羅                      |
| CRUD               | 明細の作成（追加）・参照（表示）・更新（数量変更）・削除（0指定）                     | 操作の対応が明確。抜けの検出に有効                 | RISK-001、SR-CART-01                       | 4操作それぞれに観点を置く                       |
| エラー推測         | 二重実行、古い状態での操作（競合）                                                    | 仕様が方式を定めないため、既知の失敗パターンで補う | RISK-008、RISK-010                         | 競合時の表示は TR-006 ブロック中                |
