## テスト重点

1. **数量上限（RK-CART-01, 02）**: min(在庫数, 購入上限数, 99)の境界。最も重い重点。
2. **ログイン時統合（RK-CART-04, 05）**: 除外判定の網羅、ゲストカートの終端化。
3. **表示・チェックアウト境界の再検証（RK-CART-06, 07）**: 問題明細がある状態でチェックアウトへ進めないこと。
4. **状態遷移（RK-CART-05）**: active → abandoned / consumed の終端。
5. **ロール制限（RK-CART-10）**: 顧客・ゲストのみ利用可能。

重点外（記録のみ）: 表示順（提案のため）、負数・小数（保留）、二重実行方式（保留）。

## テストレベルと観測方法

| 対象                                                 | テストレベル                                    | 観測方法                                               | 理由                                                       |
| ---------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------- |
| 数量上限・合算・0削除の判定                          | ドメイン / アプリケーション層（ユニット・統合） | ユースケースの戻り値、カートの状態                     | 境界が多く、UIより低いレベルで網羅できる                   |
| ログイン時統合の結果（明細・除外・ゲストカート状態） | 統合（アプリケーション層＋ストア）              | 統合後のカート明細、ゲストカート状態、カートバージョン | 結果の一致確認は状態で観測する                             |
| 表示時・チェックアウト開始時の再検証                 | 統合 + E2E（web-desktop）                       | 画面の問題表示、チェックアウト遷移の可否               | 利用者から見える結果が要る                                 |
| 画面状態（default / empty / invalid-items）          | E2E（UI観測）                                   | 画面表示、操作可能なUI要素                             | SCREEN-STOREFRONT-CARTの状態契約                           |
| android表示（default）                               | E2E（ネイティブ）の範囲                         | 画面表示、数量操作                                     | 必須プラットフォーム。ネイティブ許可シナリオの範囲内に限る |

観測の注意: 期待結果は仕様（BR / AC）と正本の状態に基づく。非正本（SRC-007）の値、シードの在庫・上限値（`src/seeds/scenarios.ts`）はテストデータ要件であり、仕様の期待値ではない。
