# テスト分析: カート

## テスト分析範囲

- 対象機能 / 変更: カート（既存機能の全体。改版差分: BR-CART-001 の数量上限 99 → 50、`product-change-spec.diff`）。対象は BR-CART-001〜003、AC-CART-001〜003、SCREEN-STOREFRONT-CART（`product/docs/spec/features/cart.md`）。
- 案件固有のテスト目的 / 重点: 数量上限の厳守、ログイン時統合の正確さ、チェックアウト前の再検証と価格承認。
- テストレベル: 既定はシステムテスト（Web UI上の操作と観測）。ドメイン規則の数値境界を下位レベルへ移す案は保留（`05` P-07）。
- 環境制約: 固定シードとシナリオで再現。価格変更の専用シナリオは現存しない（testability観点）。
- 対象外: 注文変換・チェックアウト本体（checkout-and-payment 側）、キャンセル・返品、ゲストチェックアウト（product-scope で対象外）、クーポン・ポイント。
- ブロッカー: 期待結果が決まらない規則が5件（U-01, U-04, U-05, U-06, U-07）。該当条件のみブロック中。
- 対象 / 実行範囲: テスト分析

## 選択したテスト技法

| テスト技法           | 適用領域                                           | 選択理由                     | 関連プロダクトリスク / 現在有効な仕様根拠 | `test-condition-design`への着眼点 |
| -------------------- | -------------------------------------------------- | ---------------------------- | ----------------------------------------- | --------------------------------- |
| 境界値分析           | 数量の上限（3種の最小値）                          | 上限判定は境界で誤りやすい   | RISK-001, BR-CART-001                     | 在庫・購入上限・50の各境界、0指定 |
| 同値分割             | 役割、画面状態、除外理由の種類                     | 分類が明確                   | RISK-004, RISK-006, BR-CART-002           | ロール×アカウント状態、画面状態   |
| デシジョンテーブル   | ゲスト・会員の統合（存在、上限内外、除外理由）     | 条件の組合せで結果が変わる   | RISK-002, BR-CART-002                     | 存在×上限×除外理由                |
| 状態遷移             | ゲストカートの active→abandoned と終端後の操作拒否 | 終端規則が仕様にある         | RISK-002, STATE-CART                      | 終端状態からの変更                |
| CRUD                 | 明細の追加・数量変更・削除・参照（会員とゲスト）   | 操作の種類ごとに規則が異なる | RISK-001, BR-CART-001                     | 作成・読取・更新・削除の各操作    |
| ペアワイズ（2-wise） | 再検証の4要素（公開、ランク、価格、在庫）          | 4要素の組合せが多い          | RISK-003, BR-CART-003                     | 要素の組合せと各要素の境界        |
| フロー               | ログイン→統合→カート表示→チェックアウト開始        | 経路の順序で結果が変わる     | RISK-002, RISK-003                        | 正常経路と各阻止経路              |
| エラー推測           | 二重実行（同時の更新要求）                         | 規約はあるが観測の定義が無い | RISK-005                                  | 同時2要求の期待結果（A-03）       |

非採用: ランダムテスト、メタモルフィックテスト（規則が明確で期待結果を先に定められるため不要）。

| ゲストカートの終端化                     | 可                                   | 一部（状態は画面からは直接見えない） | 一部               | システムテスト               | 状態の観測手段が必要（テストデータ要件）                        |
