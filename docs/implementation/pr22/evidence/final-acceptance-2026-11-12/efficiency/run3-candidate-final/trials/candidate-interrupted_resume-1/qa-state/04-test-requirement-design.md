# 04 テスト要求（test-requirement-design）: カート

入力: `01-spec-analysis.md`（再利用）、`02-question-analysis.md`、`03-test-analysis.md`。
対象 / 実行範囲: テスト要求。

## 要求範囲

- 対象機能: カート（`product/docs/spec/features/cart.md`）、画面 `SCREEN-STOREFRONT-CART`
- テストレベル: システムテスト（既定）
- 対象外: チェックアウト・注文への変換（`checkout-and-payment.md`、`orders.md`）、商品詳細の追加ボタン活性（`storefront.md`）、ログイン処理そのもの（`authentication.md`）、`consumed` 状態（注文側）
- 仮定 / 未解決事項: `02-question-analysis.md` の Q-01〜Q-12。ブロック中 TR は「備考」列に Q-ID を示す。仮定は置いていない。

## 記載ルール

- 「何を検証するか」だけを書く。条件・組合せ・手順は書かない（`05-test-condition-design.md` へ送る）。
- 期待挙動は現在有効な SPEC（cart.md の BR / AC / 画面状態）に限る。INFERENCE（INF-001〜004）は使わない。
- ブロック中の TR は削除せず、残したうえで備考に理由を付ける。
