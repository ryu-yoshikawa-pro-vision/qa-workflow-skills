## 1. 分析範囲 / 制約

- 対象機能 / 変更: カート機能の既存仕様（`features/cart.md`）全体。変更差分の入力はなく、今回は**変更影響ではなく機能全体の初回分析**として扱う（変更影響マップは空）
- 案件固有のテスト目的 / 重点: 案件のProject Context（QA用）は作成されていない。`product/docs/PROJECT_CONTEXT.md`はCodex運用用の文書であり、QA方式の正本ではない。そのため、既定のリスクマトリクスを使う
- テストレベル: システムテスト（既定）。統合・原子性（統合、並行更新）は**別テストレベル候補**として`test-architecture-design`で判断する
- 環境制約: web-desktop（主要）、android（`default`画面のみ必須）。観測手段の詳細は`test-architecture-design`
- 対象外: `02-question-analysis.md`のとおり。注文作成、ログインUI、価格計算の算出規則、在庫管理
- ブロッカー: 局所のみ（Q-CART-01〜04）。影響するTRは`02`の§3参照

## 6. 選択したテスト技法

| テスト技法         | 適用領域                                                                       | 選択理由                                                   | 関連プロダクトリスク / 仕様根拠             | `test-condition-design`への着眼点                                  |
| ------------------ | ------------------------------------------------------------------------------ | ---------------------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------ |
| 境界値分析（3値）  | 数量の上限（在庫数、購入上限数、99）と超過                                     | 順序のある値で挙動が境界で変わる。影響度が高い（RISK-001） | RISK-001、SPEC-CART-001〜002、AC-CART-001   | 上限ごとに、上限−1・上限・上限+1。どの上限が有効かで分ける         |
| 同値分割           | 利用可能者（ゲスト、顧客、オペレーター、管理者）、プラットフォーム、会員ランク | 同じ挙動になる値のまとまりが明確                           | RISK-007, 009、SPEC-CART-009、SPEC-CART-021 | 各パーティションの代表を1つ以上                                    |
| デシジョンテーブル | 統合の除外（非公開、ランク不足、無効SKU、在庫0）                               | 複数条件の組合せで結果と理由が決まる。列挙漏れの危険       | RISK-003、SPEC-CART-005                     | 16ルールを実行可能ルールとして列挙。成立不能はなし（制約は未確認） |
| 状態遷移           | カートの状態（active → abandoned）、明細の問題状態とチェックアウトのゲート     | 現在状態とイベントで結果が変わる                           | RISK-003, 004、SPEC-CART-006、020、011      | 有効遷移の全件                                                     |
| CRUD               | 明細の作成・更新・削除                                                         | 明細の操作が中心。完全性の確認に向く                       | RISK-002、SPEC-CART-001〜003                | 作成（追加）、更新（数量変更）、削除（0指定）の操作の網羅          |
| エラー推測         | 二重実行、並行更新、統合の途中失敗（保留部分を除く）                           | 既知の失敗仮説（SPEC-CART-011、test_strategyの統合不整合） | RISK-006、SPEC-CART-011                     | 仮説ごとの検証目的を明記。期待結果は仕様に基づく                   |

採用しない技法: ペアワイズ（因子が少なく、決定表で足りる）、ランダム（期待結果の仕様根拠が不足）、メタモルフィック（明示された関係がない）、スキーマ・UI（画面状態は仕様で固定）、文法（入力の文法が定義されていない）。
