## 2. テスト重点

1. 数量上限の判定（PR-01, PR-02）— 上限の3値と合算・0削除・拒否時の維持。
2. ゲスト→会員のログイン統合（PR-03）— 合算・除外・理由・状態遷移。
3. 表示時・チェックアウト開始時の再検証（PR-04, PR-05）— 公開・権限・価格・在庫・ランク・価格承認。
4. ロール制御と状態（PR-07）— ゲスト・会員のみ利用可、停止中のアクセス。

重点外（今回は設計深度を下げる）: PR-06（二重実行は観測方法が未定義のため、仕様確定後に深める）、PR-08（代表確認）。PR-09・PR-10 は仕様確定（Q-09・Q-10）後に設計する。

## 3. 変更影響

初回分析のため、既存テストとの差分は対象外。影響範囲は、カート画面（`/cart`）、ログイン処理（統合）、チェックアウト開始（再検証の境界）、在庫・価格の参照。チェックアウト・注文の変換は `checkout-and-payment.md` と `orders.md` の対象であり、本分析の範囲外。

## 4. テストレベル・観測方法

- テストレベル: **システムテスト**（既定。ユーザーや案件からの別指定なし）。
- 観測: 画面上の数量・合計・問題表示・理由表示（web-desktop 必須。android は default のみ必須）、ログイン前後のカート内容、チェックアウト開始の可否（遷移できるか）。
- 単体・結合レベルの確認（ドメインの最小値計算、統合ロジック）は、テストアーキテクチャ決定時に `test-architecture-design` へ委ねる（今回は決めない）。
- E2E選定（`e2e-test-selection`）は依頼されていないため、実施していない。

## 5. テストの可測性（testability）

- 数量上限の3値（在庫数・購入上限数・99）は、テストデータで任意に設定できることが前提。設定方法は未確認（シナリオ `cart-with-invalid-items` など既存シードは `src/seeds/scenarios.ts` を参照すべきだが、今回は未読）。
- ブロッカー（02参照）により、一部の期待結果は確定できない。
- 実対象の現在の挙動は未観測。今回は仕様のみを根拠にした。

## 6. 適用技法（候補）

| 技法                         | 適用対象                                                 | 理由                       |
| ---------------------------- | -------------------------------------------------------- | -------------------------- |
| 境界値分析                   | 数量（上限 −1 / ちょうど / +1、0）                       | 上限判定の境界が明確       |
| 同値分割                     | 上限の最小値の出所（在庫・購入上限・99）、統合の除外理由 | 出所ごとに判定結果が変わる |
| デシジョンテーブル           | 追加・変更時の合算判定、統合の除外、表示時の再検証       | 条件の組合せで結果が変わる |
| 組合せ（最小値の順序・同値） | 在庫・購入上限・99の大小関係                             | 3値の順序と同値の組合せ    |
| 状態遷移                     | ゲストカート（active → abandoned）、チェックアウトゲート | 状態の遷移規則が仕様にある |
| CRUD                         | カート明細の追加・数量変更・削除（ゲスト・会員）         | 操作ごとの結果が異なる     |
| フロー（経路）               | ゲストで追加 → ログイン → 統合結果確認                   | 統合の一連の流れ           |
| エラー推測（低）             | 不正入力、二重実行                                       | 仕様未確定のため最小限     |

## 7. 対象外・残存リスク

- チェックアウト内部（配送・決済・注文作成）は対象外（`checkout-and-payment.md`）。ただし「チェックアウト開始時の再検証」はカート側の受入として対象に含む。
- 注文変換（cart → order、カートの consumed）は対象外。
- 性能・負荷は対象外（仕様なし）。
- 残存リスク: PR-05（承認の仕組み未定義）、PR-06（観測方法未定義）、PR-09（永続化、仕様未確定）。承認後に扱う。
