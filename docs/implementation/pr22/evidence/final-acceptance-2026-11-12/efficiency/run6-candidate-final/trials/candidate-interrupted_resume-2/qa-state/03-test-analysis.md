# 03 テスト分析（test-analysis）— カート機能

## テスト分析範囲

- 対象機能 / 変更: カート（ゲスト / 会員）。商品追加・数量変更・削除・表示時 / チェックアウト開始時の再検証・ログイン時のゲストカート統合（新規・変更機能ではなく、現行仕様全体のQA）
- 案件固有のテスト目的 / 重点: 数量上限の厳守、統合結果の正しさ、価格・在庫・権限の再検証によるチェックアウト前の誤請求・誤注文の防止
- テストレベル: **システムテスト**（ユーザー・案件コンテキスト・既存有効成果物に指定なし。既定を適用）
- 環境制約: 対象画面 `/cart` の web-desktop（必須）、android（`default`のみ必須）。`product/` に `.git` がなく、依頼文の commit 2a8bcf57 は照合不可（入力は内容ハッシュで管理、`workflow-state.md`参照）
- 対象外: 注文変換・決済（checkout-and-payment / orders）、チェックアウト開始の詳細、商品詳細からの追加ボタンUI（storefront）、サインアップ時の統合（PEND-02で保留）
- ブロッカー: 0件。局所保留は `02-questions.md` の PEND-01〜09 に限定し、全体は停止しない
- 対象 / 実行範囲: テスト分析のみ（TC・実行・E2E・非E2E testwareは対象外）

## 選択したテスト技法

| テスト技法                     | 適用領域                                                                           | 選択理由                                     | 関連プロダクトリスク / 現在有効な仕様根拠     | `test-condition-design`への着眼点                           |
| ------------------------------ | ---------------------------------------------------------------------------------- | -------------------------------------------- | --------------------------------------------- | ----------------------------------------------------------- |
| 境界値分析                     | 在庫数・購入上限数・99の各上限                                                     | 単一変数の上限判定で境界が明確               | RISK-001 / SPEC-CART-001〜002                 | 各上限の -1 / 0 / +1 を、他の上限が拘束しない状態で作る     |
| Domain Testing（決定表と併用） | 有効上限 = min(在庫数, 購入上限数, 99)の判定                                       | 3変数の最小値と同率の組合せ                  | RISK-001 / SPEC-CART-001                      | どの上限が最小になるか、同率の組合せを条件として分ける      |
| 同値分割                       | 数量入力の区分（0 / 有効範囲 / 上限超過）、同一SKUか否か                           | 区分ごとに期待が異なる                       | RISK-001 / SPEC-CART-001〜003                 | 非整数・負数の期待は仕様根拠がないため保留と明記する        |
| 決定表                         | 統合の除外（非公開、ランク不足、無効SKU、在庫0、上限超過）、ロール・アカウント状態 | 複数条件の組合せで結果が決まる               | RISK-002 / RISK-005 / SPEC-CART-005、009、016 | 5つの除外条件を単独で確認し、複数該当時は保留（Q-CART-015） |
| 状態遷移                       | ゲストカートの active → abandoned、終端状態の変更不可、統合の成功 / 失敗           | 状態の遷移と終端が仕様で明示                 | RISK-002 / RISK-004 / SPEC-CART-006、018      | 統合失敗の遷移は保留（PEND-07）                             |
| CRUD                           | 明細の追加・数量変更・削除、最後の明細の削除                                       | 操作ごとに結果が異なる                       | RISK-001 / SPEC-CART-001〜003、013            | 「最後の明細を削除したとき `empty` 状態になる」を含める     |
| エラー推測                     | 更新中の連続操作（二重実行）                                                       | 仕様は「防止」のみで、観測可能な挙動は未定義 | RISK-006 / SPEC-CART-011                      | PEND-06の承認までは期待を置かない                           |

## 対象外 / 他機能への委譲

- 注文変換・チェックアウト側のカートバージョン検証（checkout-and-payment BR-CHECKOUT-002）: 他機能のテスト対象。本QAではカート側の境界（再検証の受け手）だけを扱う

- Androidの `empty` / `invalid-items`: SRC-01の必須プラットフォーム表に含まれないため対象外（Q-CART-016、提案のみ）
