# 03 テスト分析: カート機能

## テスト分析範囲

- 対象機能 / 変更: カート（数量変更・削除・ログイン時統合・表示時とチェックアウト開始時の再検証）。新規・変更の区別は、本機能が現在の製品仕様の既存機能であるため「既存機能の全体テスト」として扱う。
- 案件固有のテスト目的 / 重点: 金銭・在庫に直結する数量の上限判定、ログイン時統合の正しさ、購入不可商品がチェックアウトへ進まないこと。
- テストレベル: 既定のシステムテスト（UI操作による検証）。下位レベル（アプリケーション層の統合テスト）を併用するかは test-architecture-design の判断（対象外。引き継ぎ事項 H-01）。
- 環境制約: Web（desktop）と Android（ネイティブ）。iOS は仕様上ビルド限定契約のため、自動検証の保証対象外（残存リスク R-03）。
- 対象外: 注文データへの変換、注文確定・決済、見た目のピクセル一致（`unresolved-specifications.md` で未確定）、ストアフロントの商品一覧・詳細（カート追加の入口は SPEC-013 の範囲のみ）。
- ブロッカー: 6件（`02-question-analysis.md` のブロック中範囲）。該当するリスク評価の入力は残存要因として扱う。
- 対象 / 実行範囲: テスト分析

## 選択したテスト技法

| テスト技法                         | 適用領域                                 | 選択理由                         | 関連プロダクトリスク / 現在有効な仕様根拠        | `test-condition-design`への着眼点            |
| ---------------------------------- | ---------------------------------------- | -------------------------------- | ------------------------------------------------ | -------------------------------------------- |
| 同値分割・境界値分析               | 数量の上限判定（在庫数・購入上限数・99） | 数値の範囲規則が明確             | RISK-001〜003, SPEC-001                          | 最小値の入れ替わり、±1、0                    |
| デシジョンテーブル                 | ログイン時統合の除外判定                 | 複数条件の組合せで結果が決まる   | RISK-004, RISK-005, SPEC-002                     | 統合対象・除外理由の組。上限超過の扱いは保留 |
| 組合せ（ペアワイズ）               | 再検証の要因（公開、権限、価格、在庫）   | 要因が多く全組合せは過大         | RISK-006, SPEC-003                               | 2-wise で要因間を網羅                        |
| 状態遷移                           | Cart の状態（active → abandoned、終端）  | 状態規則が明確                   | RISK-010, SPEC-010                               | 遷移の有効・無効                             |
| CRUD / 権限マトリクス              | 利用主体 × 操作                          | 権限表が明確                     | RISK-009, SPEC-009                               | 主体ごとの可否                               |
| 画面状態・表示のチェック（一覧型） | 画面状態と表示項目                       | 状態表と表示項目が定義されている | RISK-011, RISK-013, SPEC-004, SPEC-005, SPEC-014 | 状態×プラットフォーム                        |
| 推測（エラー推測）                 | 二重実行、並行操作                       | 仕様の空白を探る                 | RISK-008, UNK-007, UNK-009                       | 同一操作の二重送信                           |
