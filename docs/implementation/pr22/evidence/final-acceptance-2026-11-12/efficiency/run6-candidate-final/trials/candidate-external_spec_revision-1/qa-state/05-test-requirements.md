# 05 テスト要求（test-requirement-design）— カート

入力: `01-spec-authority.md`（SPEC根拠）、`04-test-analysis.md`（PR-01〜PR-10、重点、レベル＝システムテスト）、`02`・`03`（ブロッカー・保留）。
要求は「何を検証・保証するか」に限る。具体的な数値・組合せ・手順は `06-test-conditions.md` 以降へ送る。

状態の意味: `有効` = 現在の仕様根拠で検証責務を確定できる。`一部ブロック中` = 検証責務は確定するが、括弧内の論点の期待結果は保留。`ブロック中` = 期待結果が確定できないため、要求を有効化しない（要求の文言だけ記録）。

## 注意

- 「有効」の TR も、期待結果は `06-test-conditions.md` で条件化してから確定する。
- 「ブロック中」の TR は要求を有効化しない。承認後に `spec-analysis` で反映し、`要再検証` として再設計する。
- 追加の TR（仕様から導けない新しい検証責務）は作っていない。
