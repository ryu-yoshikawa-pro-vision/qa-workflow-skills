# 06 テスト観点・条件設計（test-condition-design）— カート

入力: `05-test-requirements.md`（TR-CART-001〜027）、`01`（SPEC）、`02`・`03`（ブロック中・保留）。
本書は「どの条件・観点で検証するか」と「カバレッジ項目」を定義する。期待結果の具体値や手順は `test-case-design` へ送る。期待結果の根拠は、各項目の「根拠」欄の SPEC ID を指す。

凡例:

- 状態 `有効`: 条件・期待結果の根拠が仕様で確定している（期待結果の具体化は test-case-design）。
- 状態 `ブロック中`: 該当する期待結果が未確定（Q番号）。項目は作るが、期待結果は作らない。
- 数値は仕様上の記号で表す（例: cap = min(在庫数, 購入上限数, 99)）。実データ値は test-case-design / テストデータで決める。
