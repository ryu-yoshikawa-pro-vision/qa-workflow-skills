## 2. ブロッカーの詳細

### Q-01 再検証時の既存数量（ブロッカー）

- 矛盾・欠落: S-01 は「操作時の超過指定」の拒否を定める。在庫が減少して既存数量が上限を超えた場合は定義がない。
- 影響: invalid-items の期待（数量表示、修正導線の内容）。
- 回答なしの扱い: 数量の変更（自動補正）は禁止の規則から推測できるが、推測で期待結果を作らない。該当 CI は保留。
- 回答例（承認者が決める内容）: 数量は保持し問題明細として表示する／数量を上限まで下げる（この場合は S-01 との整合が必要）。

### Q-02 数量入力の異常値（ブロッカー）

- 欠落: 負数、小数、非数、空、極大値の扱い。0 を「追加」操作で指定した場合の扱い（S-02 は「数量変更」の文脈）。
- 回答なしの扱い: 0 の「既存明細の削除」（S-02）と「上限超過の拒否」（S-01）は期待結果にできる。それ以外は保留。

### Q-03 価格変更の承認（ブロッカー）

- 欠落: 承認操作の場所・単位（明細単位か合計単位か）、承認後の価格表示、承認後の再変更、承認の取消。
- 用語の揺れ: cart.md は「会員の承認」、補助文書は「顧客」。承認主体が会員・顧客のどちらでも、ロールは guest / customer 両方の可能性があるため、確認が必要。
- 回答なしの扱い: 「承認まで進めない」（S-06）は期待結果にできる。承認操作の成功後の状態は保留。

### Q-04 カートのバージョン競合（ブロッカー）

- 欠落: cart.md は版数に触れていない。AC-CART-002 は統合結果の版数一致を求めるが、通常の数量変更・削除時の版数不一致の扱いは補助文書のみ。
- 回答なしの扱い: 古い版数からの操作は期待結果を作らない（TR-016 はブロック中）。

### Q-05 合計金額（ブロッカー）

- 欠落: cart.md は「合計金額」を表示するとのみ記載。計算式・税込/税抜・送料の扱いが未定義。補助文書の価格計算は注文時の計算式を示すが、カート画面の合計の定義ではない。
- 回答なしの扱い: 合計金額の「表示されること」は期待できるが、値の一致は保留。

## 3. 要確認の詳細（要点のみ）

- **Q-06**: 承認されるまでは期待結果に使わない。承認されれば統合の上限超過の期待値が確定する（PA-06）。
- **Q-07**: 正式仕様は現在価格のみ。補助文書の追加時価格表示は正式仕様ではないため、表示の有無を承認者が決める必要がある。
- **Q-09**: ゲストカートが空のとき統合は no-op か、統合元を abandoned にするか。注文後の再アクセスで新規の空カートが得られるか。
- **Q-15**: 補助文書を正本として扱うかどうかの判断。ここが決まるまで、補助文書のみに依る期待は保留。
- **Q-16**: Android の empty / invalid-items を検証対象外にするなら、残存リスクとして明示する必要がある（承認が必要）。
