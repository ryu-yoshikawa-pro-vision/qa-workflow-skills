# 03 テスト分析（test-analysis）— カート

対象 / 実行範囲: テスト分析（`E2E対象選定`は対象外）

## テスト分析範囲

- 対象機能 / 変更: カート（新規QA対象。変更差分は未提示。全機能を対象とする）
- 案件固有のテスト目的 / 重点: 数量上限の正確性、ゲストカート統合の正確性、表示時・チェックアウト開始時の再検証、価格変更の承認ゲート、版数整合
- テストレベル: **システムテスト**（案件・依頼で別レベル指定なし。既定に従う）
- 環境制約: Web（desktop）と Android の既定表示（SPEC-CART-012）。空・問題状態は web-desktop のみ（SPEC-CART-010/011）。観測の一部（版数）は UI に出ない可能性あり（後述）。準備はシナリオ名で指定（`default`、`cart-with-invalid-items`、`regular-member`、`out-of-stock`、`low-stock`、`empty-catalog`、`checkout-resume`。出典 `product/docs/spec/state-and-scenarios.md` L21）
- 対象外: 下表「対象外」参照
- ブロッカー: 全体停止なし。局所ブロックは `02_question-analysis.md` の Q-CART-001〜003 に限る

## 選択したテスト技法

| テスト技法            | 適用領域                                                                                            | 選択理由                                                                             | 関連プロダクトリスク / 現在有効な仕様根拠   | `test-condition-design`への着眼点                                           |
| --------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------- | --------------------------------------------------------------------------- |
| 境界値分析（3-value） | 数量上限（在庫・購入上限・99）、数量入力範囲                                                        | 上限の実装リスクが高い（最小値・複数条件）。境界両側の差が重要                       | RISK-CART-001、SPEC-CART-001                | 上限を決める条件ごとに境界（上限-1 / 上限 / 上限+1）。0 と 1 の下限も含める |
| Domain Testing        | 在庫と購入上限の2変数の境界（最小値がどちらで決まるか）                                             | 2変数の線形境界（在庫=購入上限）があり、同値分割だけでは境界の取り違えを検出しにくい | RISK-CART-001                               | 在庫 = 購入上限、在庫 < 購入上限、在庫 > 購入上限の各境界で ON/OFF 点を作る |
| 同値分割              | 数量入力（有効・0・負数・超過・非整数）、SKU同一性（同一SKU/別SKU）                                 | 入力の種類と判定の区別が明確                                                         | RISK-CART-001/005、SPEC-CART-001/002        | 有効範囲・無効範囲の代表値。SKU別の上限の独立性                             |
| デシジョンテーブル    | ゲストカート統合（SKU有効・公開・ランク・在庫・上限余地）、表示時の再検証とチェックアウトのブロック | 条件の組合せで結果（統合・一部統合・除外・ブロック）が変わる                         | RISK-CART-002/003、SPEC-CART-003/005/007    | 単独条件と複合条件のルール。複合時の理由表示順は保留                        |
| 状態遷移              | ゲストカート（active→abandoned）、価格変更承認（変更なし→保留→承認→再変更）                         | 有効・無効遷移が明確                                                                 | RISK-CART-002/003、SPEC-CART-004/006、SRC-3 | 有効遷移と禁止遷移（承認なしのチェックアウト、終端からの変更）              |
| CRUD                  | 明細（追加・参照・数量変更・削除）× ロール                                                          | 操作とロールの組合せが網羅可能で小規模                                               | RISK-CART-004/005、SPEC-CART-008            | 全セルの権限。状態変更の一連シーケンス（追加→変更→0で削除）                 |
| 組合せ（2-wise）      | 再検証の問題種別（2明細の組合せ）、表示項目の組合せ                                                 | 問題種別の組合せ数が中程度で、2-wise で主要な相互作用を確認できる                    | RISK-CART-003/006、SPEC-CART-005/009        | 問題種別ごとに成立可能な組合せを列挙し、2-wise を基準にする                 |
| エラー推測（限定）    | 版数の不一致・二重送信・同時操作                                                                    | 同時操作は仕様上の規定（SPEC-CART-013）があり、観測可能                              | RISK-CART-004                               | 連続送信、別画面からの同時変更                                              |

採用しない技法と理由:

- ランダムテスト・メタモルファステスト: 入力関係や分布の仕様がないため採用しない。
- 文法ベース・スキーマ / UI パターン: 入力文法・スキーマの仕様がないため採用しない（数量入力は境界・同値分割で扱う）。
- 完全組合せ: 組合せ数が過大。2-wise を基準とする。
