# 04. テスト要求（test-requirement-design）— カート機能

- 入力: `01_spec_analysis.md`（SPEC-001〜020、UNK-001〜009、C-001〜005）、`02_question_analysis.md`（Q-001〜Q-012、TR番号の割当を含む）、`03_test_analysis.md`（RISK-001〜013、テスト重点）
- 実施方法: 手作業。`requirement_structure` runtimeは未実行。Machine Entityは未付与。
- 本成果物は「何を検証するか」のみを記述し、条件・組合せ・手順は`05_test_condition.md`で扱う。

## 要求範囲

- 対象機能: カート（ゲスト・customer）の追加、数量変更、削除、再検証、チェックアウト阻止、ログイン時のゲストカート統合、表示、永続化、ロール境界
- テストレベル: システムテスト（Web / Android）を基本。統合テストレベル（API / データ層）を候補とする要求は、その旨を備考に記載
- 対象外: 注文変換・注文作成・チェックアウトの詳細（チェックアウト機能側）、管理画面、ゲストカートの保持期限（Q-009で保留）、E2E実装
- 仮定 / 未解決事項: `01`の権威判定（下記「根拠の層」）、Q-001〜Q-012。承認済みの仮定はなし（INF-001 / INF-002は使用しない）

### 根拠の層（重要）

`product/docs/spec/README.md`の「正式な製品動作」は`product-scope.md`・`roles-and-permissions.md`・`state-and-scenarios.md`・`ui-ux-contract.md`・`features/**/*.md`に限られる。`01_spec_analysis.md`の多くのSPECは`01_requirements/functional_requirements.md`（FR-CA）や`12_quality/acceptance_criteria.md`に基づくが、これらは正式仕様正本の一覧に含まれない。

- **正式（cart.md / authentication.md）**: 正式仕様として扱える根拠
- **要権威判定（P-001）**: FR-CA、acceptance_criteria、03_domain等のみを根拠とするもの。P-001で扱いが決まるまで、確定した要求としない（承認が出た時点で再確認）
