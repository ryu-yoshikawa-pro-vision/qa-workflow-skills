## 分析範囲

- 対象機能: カート（SCREEN-STOREFRONT-CART）、ログイン時のゲストカート統合（ログイン本体は対象外）
- テストレベル: **システムテスト**（ユーザー・案件コンテキスト・既存有効成果物に別レベル指定がないため既定値）
- 環境制約: web-desktop（必須）、android（`default`のみ必須。Android上の空・問題状態は仕様上の必須対象外）
- 対象外: チェックアウト・注文作成（consumed遷移・在庫減算を含む）、決済、ログイン本体、Playwright E2E選定（未依頼）

## 選択したテスト技法

| テスト技法                   | 適用領域                                                                            | 選択理由                                               | 関連プロダクトリスク / 仕様根拠                             | `test-condition-design`への着眼点                                        |
| ---------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------- | ------------------------------------------------------------------------ |
| 境界値分析（BVA）            | 数量上限 m = min(在庫, 購入上限, 99) の境界（m-1, m, m+1）、0                       | 単一スカラーの境界。min規則の境界が仕様で明示          | RISK-001 / SPEC-CART-001                                    | 在庫・購入上限・99のどれがbindingかを変えた値の組                        |
| 判定表（デシジョンテーブル） | 上限の決定要因（どの入力が最小か）、統合時の明細分類、ロール×操作                   | 条件の組合せで結果が決まる                             | RISK-001, RISK-004, RISK-006 / SPEC-CART-001, 002, 006      | 統合の条件: 超過・非公開・ランク不足・無効SKU・在庫0・会員既存数量の有無 |
| 状態遷移                     | 明細の価格承認状態、カートの状態（active → abandoned / consumed）、処理中の二重実行 | 状態と遷移が仕様で明示                                 | RISK-002, RISK-004, RISK-007, RISK-009 / SPEC-CART-003, 007 | 許可されない遷移（終端からの変更）も含める                               |
| 組合せ（ペアワイズ）         | 再検証条件（公開・購入権限・価格変更・在庫・ロール）の2-wise                        | 因子が多く全組合せは過大。2-wiseで既知の相互作用を拾う | RISK-003 / SPEC-CART-003                                    | 因子ごとの水準（在庫0・1〜5・6以上 等）は仕様の値から                    |
| 同値分割                     | 数量入力（有効域・超過域・0・無効値）、画面状態                                     | 入力域の分割で代表値を選べる                           | RISK-005, RISK-008 / SPEC-CART-001, 005                     | 無効値の側は H-01 によりブロック中                                       |
| 経路（フロー）               | カート表示 → チェックアウト開始の再検証経路                                         | 手順に意味がある                                       | RISK-002, RISK-003 / SPEC-CART-003                          | チェックアウト側の確認は境界のみ                                         |

採用しない技法: ランダム、メタモルフィック（明示された入出力関係なし）、文法（入力文法の仕様なし）、スキーマ・UIパターン（画面状態表で足りる）。
