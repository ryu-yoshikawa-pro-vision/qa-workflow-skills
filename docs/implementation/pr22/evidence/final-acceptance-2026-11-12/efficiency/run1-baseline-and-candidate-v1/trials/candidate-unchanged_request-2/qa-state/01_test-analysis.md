- 対象 / 実行範囲: テスト分析（カート機能、Web Phase 1）
- 対象製品: `product/`（commit 2a8bcf57、利用者申告）
- 主要根拠: `product/docs/spec/features/cart.md`（BR-CART-001〜003、AC-CART-001〜003、画面状態）
- 補助根拠（現在有効な仕様として採用）: `product/docs/03_domain/business_rules.md` §3 Cart（L136〜147）、`product/docs/12_quality/acceptance_criteria.md` §4（L58〜72）、`product/docs/spec/state-and-scenarios.md`（L15, L21, L27）、`product/docs/spec/roles-and-permissions.md`

## テスト分析範囲

- 対象機能 / 変更: カートへの追加、数量変更、削除、表示時・チェックアウト開始時の再検証、ログイン時のゲストカート統合、カート画面の状態（default / empty / invalid-items）。
- 案件固有のテスト目的 / 重点: 数量上限の自動補正禁止、価格改定・在庫・公開状態の再検証によるチェックアウトゲート、ゲスト→会員統合の整合性。
- テストレベル: システムテスト（既定。ユーザー・案件指定なし）。規則の網羅は結合（ユースケース）・契約レベルでの観測を後続`test-architecture-design`で検討する候補とする。
- 環境制約: シナリオ `default`、`empty-catalog`、`out-of-stock`、`low-stock`、`regular-member`、`cart-with-invalid-items`、`checkout-resume`（state-and-scenarios.md L21）。
- 対象外:
  - 注文変換（Cart → Order、`consumed`）、決済失敗時の挙動、チェックアウトセッション詳細 → `checkout-and-payment`機能
  - ゲストによるチェックアウト（Phase 1対象外、acceptance_criteria.md L163）
  - Native（Android/iOS）ランタイム動作（Web Phase 1の受入基準外、acceptance_criteria.md L163）。ただしcart.mdの`default`状態は`android`を必須プラットフォームとして列挙しているため、扱いはQ-01（保留）
- ブロッカー: なし（全体停止の根拠なし）。個別の保留はQ-01、Q-03、Q-04、Q-05、Q-08（`02_question-log.md`）。

## 選択したテスト技法

| テスト技法                 | 適用領域                                                                                                             | 選択理由                                      | 関連プロダクトリスク / 現在有効な仕様根拠         | `test-condition-design`への着眼点                |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- | ------------------------------------------------- | ------------------------------------------------ |
| 境界値分析                 | 数量上限（L = min(在庫数, 購入上限数, 99)）                                                                          | 上限判定の境界が本質                          | RISK-CART-01 / BR-CART-001、AC-CART-001           | L-1, L, L+1、0、1、3値それぞれが最小となるケース |
| デシジョンテーブル         | チェックアウトゲート（公開状態・購入権限/会員ランク・価格・在庫）と結果                                              | 複数条件の合成結果                            | RISK-CART-03 / BR-CART-003、AC-CART-003           | 明細ごとの組合せ、価格承認の有無、全明細の合成   |
| 分類木＋2-wise（制約付き） | ゲスト→会員統合（明細属性と既存会員カートの状態）                                                                    | 属性が多く全組合せは過大                      | RISK-CART-02 / BR-CART-002                        | 除外理由の一意性、同SKU合算、上限取込            |
| 状態遷移                   | ゲストカート状態（active→abandoned）、価格改定（承認待ち→承認済）、カート画面状態（empty / default / invalid-items） | 遷移と禁止遷移が仕様に存在                    | RISK-CART-02, 03, 07 / BR-CART-002、003           | 失敗時の遷移なし、承認後のみ進行可               |
| CRUD                       | カート明細の作成（追加）・読取（表示）・更新（数量）・削除（0 / 削除）×ロール×version                                | 操作種別とversion要件が明確                   | RISK-CART-04, 06 / business_rules L137〜139、L144 | 操作ごとのversion要否、増分1回                   |
| 同値分割                   | ロール（guest / customer / operator / admin）、createdAt（同値 / 非同値）                                            | 分類が明確                                    | RISK-CART-06, 08 / business_rules L136、L145      | 代表値の選定                                     |
| エラー推測（限定的）       | 二重実行・並行更新                                                                                                   | 仕様記述（cart.md L23）に根拠がある場合に限る | RISK-CART-05                                      | 期待結果は保留（Q-06）                           |
