# テスト分析: カート（cart）

## テスト分析範囲

- 対象機能 / 変更: カート機能（`product/docs/spec/features/cart.md`）。変更差分（commit 2a8bcf57の差分）は未提示のため、変更領域は特定せず、機能全体を「指定対象機能」として分析する。
- 情報源（現在有効な仕様根拠）:
  - `product/docs/spec/features/cart.md`（BR-CART-001〜003、AC-CART-001〜003、SCREEN-STOREFRONT-CART、UI・振る舞い規約）
  - `product/docs/spec/roles-and-permissions.md`（ロール別のカート利用可否: ゲスト〇、カスタマー（会員）〇、オペレーター×、管理者×）
  - `product/docs/spec/state-and-scenarios.md`（Cart: active → consumed / abandoned、終端状態からの変更禁止、カート再検証の境界）
  - `product/docs/spec/unresolved-specifications.md`（カートに関する未確定事項なし）、`known-deviations.md`（有効な既知の差異なし）
  - 参照のみ: `features/authentication.md`（ゲストカート統合への言及）、`features/storefront.md`（BR-STOREFRONT-003の追加可否）、`features/checkout-and-payment.md`（BR-CHECKOUT-002のカートバージョン・価格再検証）
- 実装コード（`src/...`、`app/cart*.tsx`）は期待値の根拠にしない。仕様書の「実行可能な正本ソース」は具体値（シナリオID、ロール値など）の解決にだけ後続工程で使う。
- テストレベル: **システムテスト**（既定。ユーザー・案件コンテキスト・有効な既存成果物に別レベルの指定なし）。
- 環境制約: 固定シナリオ `default` / `empty`相当 / `out-of-stock` / `low-stock` / `regular-member` / `cart-with-invalid-items` / `checkout-resume` が仕様上存在する（state-and-scenarios.md）。前提データはこれらを使える前提で扱う。テストアーキテクチャ（観測手段・環境方式）は未設計のため、観測方法は「UI観測＋カート状態の観測手段（要確認）」とする。
- 対象外:
  - 注文データへの変換（cart.md 目的で対象外。checkout-and-payment / orders で扱う）
  - 商品閲覧・追加可否の判定（BR-STOREFRONT-003: 在庫切れ・バリエーション未選択の追加禁止は storefront で扱う。カートは追加後の再検証で扱う）
  - ログイン・セッション処理そのもの（authentication で扱う。カートは統合の結果だけを検証する）
- ブロッカー（全体停止はしない。範囲別の保留は `02-question-analysis.md` を参照）:
  - 統合ルールの「許容上限超過分」の解釈（部分統合か明細全体除外か）、カートバージョンの定義、価格変更の承認手続き、数量の不正入力の扱い。これらに依存する期待結果は保留とする。

## Machine Runtime / Entity（機械証拠）

本分析では、`analysis_entities` / `risk_matrix` / `technique_candidates` / `change_impact` / `environment_requirements` の決定論的runtime dispatchは実行していない。入力の正規化形式を確認できず、機械証拠（runtime-v2 / entity-state-v2）を手組みしないため、本ファイルに runtime 結果は含めない。このため、最終runtime evidence gate（`verify_runtime_evidence`）も未実施であり、本成果物は機械検証済みの完成物ではない。
