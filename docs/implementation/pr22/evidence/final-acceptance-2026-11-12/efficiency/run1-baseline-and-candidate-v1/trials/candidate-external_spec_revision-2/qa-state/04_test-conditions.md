- 入力: `03_test-requirements.md`（TR-CART-01〜18）、`01_test-analysis.md`、`02_question-log.md`
- 作成日: 2026-11-13
- 方針: 各条件はTRへ接続する。期待結果は具体化せず、仕様根拠に基づく「判定の方向」だけを示す。判定が保留のものは「保留」と明記し、期待結果を創作しない。手順・テストデータの具体化は `test-case-design` へ委ねる。

## 記号

- L = min(在庫数 S, 購入上限数 P, 50)。L は SKU ごとに算出する。50 は BR-CART-001（改版後）の値で、Q-16 の仮定に従う。
- 「判定の方向」: 受理 / 拒否 / 削除 / 不変（既存数量・既存状態の維持）/ 保留

## 後続への引継ぎ（test-case-design）

- 数量上限条件は CND-CART-001〜013 を優先してTC化する。
- ゲスト統合は分類木の2-wiseから、既存のTR-08〜10に対応するTCを作る。
- 保留条件は回答後に確定する。回答前に期待結果を埋めない。
- カバレッジ項目の充足判定（coverage-analysis）は、TC化後に実施する。
