# 03 テスト分析: カート機能

## テスト分析範囲

- 対象機能 / 変更: カート機能全体（既存機能のQA）。改版（2026-11-13）: BR-CART-001の上限値 99 → 50 を反映（`change-impact-product-change-spec.md`）
- 案件固有のテスト目的 / 重点: 金銭に直結する数量・価格・承認ゲート、ログイン時統合の正しさ
- テストレベル: システムテスト（既定）。Web（web-desktop）とAndroid（ネイティブ）でUI観測する
- 環境制約: iOSは保証範囲がビルド限定（SPEC-012）。iOSでのカート振る舞いの自動検証は本分析の対象外として残存リスク扱い
- 対象外: 注文変換（consumed）、決済・再決済、注文確認・注文作成時の再検証、認証画面そのもの（統合の結果のみ対象）
- ブロッカー: `02-question-analysis.md`のQ-001, Q-002, Q-007, Q-008, Q-009, Q-011（局所）
- 対象 / 実行範囲: テスト分析

## 選択したテスト技法

| テスト技法            | 適用領域                                                           | 選択理由                                                         | 関連プロダクトリスク / 現在有効な仕様根拠 | `test-condition-design`への着眼点                                      |
| --------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------- | ----------------------------------------- | ---------------------------------------------------------------------- |
| 境界値分析（3-value） | 数量上限（min(在庫, 購入上限, 50)）、加算後の合計（改版: 99→50）   | 境界ロジックが複雑（最小値）、境界実装リスクが高い               | RISK-001, SPEC-002, SPEC-007              | 3要素それぞれを限定要素として、L-1 / L / L+1 を項目化。L≥2の前提を明示 |
| デシジョンテーブル    | 操作種別（加算・絶対値変更）×上限判定、削除                        | 操作種別と結果の組合せで結果が決まる                             | RISK-001, SPEC-002                        | 実行可能ルールを項目化。加算0・負数はブロック中                        |
| 組合せ（2-wise）      | 再検証の4判定次元（公開、権限、価格、在庫）                        | 独立した判定次元の相互作用を確認する必要がある。全組合せは16通り | RISK-002, SPEC-004                        | 全2-wise項目を覆う。単独不備を加える                                   |
| 同値分割              | 空状態の成立経路、利用ロール、除外理由、問題種別、プラットフォーム | 挙動が同じになる入力群に分けられる                               | RISK-006, RISK-009, RISK-003, RISK-008    | 各パーティションを1つ以上                                              |
| 状態遷移              | 価格変更の承認ゲート、統合元ゲストカート（active → abandoned）     | 状態と遷移で挙動が変わる                                         | RISK-004, RISK-003, SPEC-003, SPEC-010    | 有効遷移を全件カバー。再変更後の遷移は候補のみ                         |
| エラー推測            | 二重実行、統合の境界（空、失敗、再統合）                           | 既知の失敗パターン。cart.mdのUI規約に由来                        | RISK-005, SPEC-005                        | 採用仮説を明示。期待結果は承認後に確定                                 |
| シナリオ              | ゲスト追加→ログイン→統合→チェックアウト開始                        | 複数の境界をまたぐ主経路                                         | RISK-003, RISK-002                        | 主経路を1本                                                            |
