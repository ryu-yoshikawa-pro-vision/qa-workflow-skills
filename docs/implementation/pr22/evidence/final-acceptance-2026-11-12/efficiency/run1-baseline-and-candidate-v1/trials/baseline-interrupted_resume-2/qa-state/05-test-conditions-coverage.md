# 05 テスト観点・条件 / カバレッジ項目: カート（test-condition-design 相当）

- 入力: `04-test-requirements.md`（TR-001〜TR-031）、`03-test-analysis.md`、`02-question-analysis.md`
- テストレベル: システム
- 対象外: 注文作成・決済、商品詳細からの追加可否、管理者による在庫・価格の操作（03 §7）
- 仮定 / 未解決事項: 02 の Q-01〜Q-16、Q-17（新規候補）。ASM-CART-CAND-01（I-01）は未承認のため期待値に使わない

## 0. 扱いの凡例

- **根拠**: `SPEC` = cart.md 等の正式仕様に明記（S-xx / BR-xx / AC-xx）。`DERIVED` = SPEC を当てはめた結果（D-xx）。`BLOCKED(PA-xx)` = 期待値の根拠が未承認。その CI は期待結果を定義しない
- **CI の状態**: `確定` / `ブロック中`（PA-xx の承認待ち）
- 期待結果の具体値、手順、テストデータは `test-case-design` の担当。ここでは「何を条件として取るか」と「期待挙動の根拠」だけを定義する
- 数量の具体値（L = 上限）は、在庫数・購入上限数の組合せとして表す。L の値そのものは `test-case-design` で決める

## 1. テスト条件へ展開しないテスト要求

| テスト要求ID                                        | 扱い       | 理由 / 根拠                                            |

| TR-017 の一部（負数・小数・非数・空・極大値の扱い） | ブロック中 | PA-02。CI は作成するが期待値は保留（TCN-018 CI03〜05） |
| TR-007（既存数量の超過）                            | ブロック中 | PA-01。CI は作成するが期待値は保留（TCN-007 CI03〜04） |

## 6. 追跡性（要約）

- TR-001〜TR-031 のすべてに TCN が1つ以上対応する（TR-004 / 015 / 025 は2つ以上の TCN に対応）
