# 02 不明点・矛盾（question-analysis）— カート

分類: ブロッカー / 要確認 / 仮定可能 / 提案・任意。
「仮定可能」は仕様ではない。期待結果の根拠に使う場合は承認済みASMとして分離する（承認は `06_pending-approvals.md` で保留）。
承認者はProject Contextで定義されていないため、本ファイルでは特定しない（「製品の承認権限者」と表記）。

## 質問詳細

### Q-CART-001 矛盾（ブロッカー・局所）

- 論点: 上限超過で拒否された追加・数量変更で、親カートの版数が増えるか。
- 根拠の対立:
  - SUP-7 `acceptance_criteria.md` L61: 「購入上限数超過時の追加拒否」を含む変更操作で、親カート版数が「1回ずつインクリメント」される。
  - SUP-1 `business_rules.md` L137: 操作全体を拒否し、現在の数量を維持する。L144: 版数は変更と同一トランザクションで更新する。
  - SRC-1 `cart.md` BR-CART-001: 操作全体を拒否し、変更前の数量を維持する（版数には触れていない）。
- 影響: 拒否時に版数が変わると、チェックアウトの版数不一致判定に影響する。
- 回答なしの扱い: 拒否時の版数期待結果を作らない。拒否時の「数量が変わらないこと」は SPEC-CART-001 だけで検証する。
- 回答の正規化先: 承認済みの版数規則として SPEC 化するか、INF-CART-003 を修正する。SUP-7 L61 の修正要否も併せて判断。
- 再開先: `test-condition-design`（TCN-CART-009）。

### Q-CART-002 要確認（局所）

- 論点: 追加操作（相対数量）で0・負数・非整数を指定した場合の扱い。
- 根拠: SUP-3 L44 は「数量 1〜99の整数」とする。SPEC-CART-002 の「0で削除」は数量変更（絶対数量）の規則として読める。
- 提案（承認を求める案）: 追加の0・負数・非整数は入力検証で拒否し、カート内容は変更しない。
- 回答なしの扱い: 当該入力の期待結果は作らない。
- 再開先: `test-condition-design`（TCN-CART-003）。

### Q-CART-003 要確認（局所）

- 論点: 統合対象のゲストカートが空、または全明細が除外された場合に、ゲストカートを `abandoned` にするか。
- 根拠: SPEC-CART-004 は「統合元のゲストカートは abandoned へ遷移する」と書くが、対象がない場合の規定はない。
- 提案: 統合対象の有無にかかわらず、統合処理が成功すれば `abandoned` とする（SPEC-CART-004 の文言に従う）。
- 回答なしの扱い: 空・全件除外の遷移を期待結果にしない。
- 再開先: `test-condition-design`（TCN-CART-006）。

### Q-CART-004 仮定可能（承認待ち）

- 論点: ゲストカート統合の「許容上限」は、SPEC-CART-001 の最小値（在庫数・購入上限数・99）と同じか。
- 根拠: SPEC-CART-003 は「許容上限」と書くが定義がない。SUP-1 L146 は「購入許容上限」と記載。
- 提案: INF-CART-001 として、SPEC-CART-001 と同じ最小値とする。
- 扱い: 承認されるまで、統合の上限境界は「SPEC-CART-001 と同義とした暫定」と明示して条件化し、期待結果には承認済みASMとしてのみ使う。

### Q-CART-005 仮定可能（承認待ち）

- 論点: 版数増分の規則（初回追加、成功時の1増分、統合時の増分）、価格改定承認の単位（カート単位か明細単位か）、合計金額の計算式（会員割引・端数処理）。
- 根拠: SUP-1、SUP-7 L62・L66、SUP-8 L50 に記載があるが、正本（SRC-1）には記載がない。
- 扱い: 承認まで、版数・合計金額の期待結果は保留。価格承認を必要とする規則（SPEC-CART-006）そのものは正本に基づき継続。

### Q-CART-006 提案・任意（局所）

- 論点: 複数の問題（価格変更・在庫不足・公開停止等）や複数の除外理由が同時にある場合の表示順。
- 根拠: 正本に規定なし。探索報告 `product/docs/reports/2026-08-01_ui-ux-user-journey-deep-exploration.md` L524 も「未確認」と記載。
- 扱い: 個別の問題の検出・表示・チェックアウトのブロックは継続。順序の期待結果だけ保留。

### Q-CART-007 仮定可能（承認待ち）

- 論点: ゲストIDの保持（同一ブラウザ再訪時の再取得）と、端末ストレージ削除時の挙動。
- 根拠: SUP-1 L143 は再訪時の取得のみ。削除時は未規定。
- 扱い: 再訪時の取得は承認まで候補。削除時は未規定のため、条件化せず「ブロック中」とする。

### Q-CART-008 要確認（正本化要求）

- 論点: 版数規則、表示順、ゲストID保持、絶対/相対数量の区別が正本 `cart.md` に無く、補助文書にのみある。
- 対応: 本QAは正本を変更しない。製品側で `product/docs/spec/change-process.md` の手続きにより正本化するかの判断を求める。
- 扱い: 正本化されるまで、これらの規則は候補（INF）として扱い、期待結果の根拠にしない。

### Q-CART-009 提案・任意

- 論点: 二重実行防止の方式（SPEC-CART-013）。
- 提案: 方式は指定せず、観測結果（同一操作の連打・同時送信で反映は1回、版数増分も1回）で検証する。

### Q-CART-010 提案・任意（追跡性）

- 論点: `cart.md` の `empty` 状態の関連オラクルが `BR-CART-001` を指している。空状態を規定するBRがない。
- 提案: 仕様所有者が関連オラクルを見直す（本QAでは変更しない）。
