# 05. テスト観点・条件 / カバレッジ項目（test-condition-design）— カート機能

- 入力: `04_test_requirement.md`（TR-001〜024）、`01_spec_analysis.md`、`02_question_analysis.md`、`03_test_analysis.md`
- 実施方法: 手作業。`condition_structure`および各技法runtimeは未実行。Machine Runtime Result / Entityは未付与。
- 技法の規則は`test-condition-design`の`references/coverage-techniques.md`を参照せず、一般的なBVA・同値分割・デシジョンテーブル・状態遷移の定義に従って手作業で設計した（上記の制約として残す）。
- 本成果物は条件・観点と、カバレッジ項目（CI）までを扱う。実行手順・テストデータの具体値・詳細な手順は`test-case-design`へ委ねる。
- 表記: 「期待」列は仕様根拠で言えることだけを書く。根拠が無いものは期待を空欄とし、状態を`保留`または`ブロック中`にする。

## 観点範囲

- 対象テスト要求: TR-001〜TR-024（うち一部はブロック中・保留）
- テストレベル: システムテスト（Web / Android）。統合テスト候補（版数、active一意性、並行性、統合失敗の注入）は観点として残し、レベルの最終確定は`test-analysis`の残存リスクに従う
- 対象外: 注文変換・注文作成の詳細、管理画面、保持期限（Q-009）
- 仮定 / 未解決事項: 04の「根拠の層」（P-001）、Q-001〜Q-012。承認済みの仮定はなし
