## 2. 仕様事実の分類

### SPEC（cart.md / 正式正本に明記）

| ID   | 内容                                                                                                                                                        | 出典                                 |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| S-01 | 同一SKUは合算して判定し、上限は在庫数・購入上限数・99の最小値。超過指定は自動補正せず操作全体を拒否し、変更前の数量を維持する                               | BR-CART-001, AC-CART-001             |
| S-02 | 数量0の指定は該当明細をカートから削除する                                                                                                                   | BR-CART-001                          |
| S-03 | ログイン時は会員カートを基準に、ゲストカートをSKU単位で統合する。許容上限超過分、非公開商品、会員ランク不足、無効SKU、在庫0は統合対象外とし、理由を明示する | BR-CART-002, AC-CART-002             |
| S-04 | 統合元のゲストカートは abandoned へ遷移する                                                                                                                 | BR-CART-002, state-and-scenarios     |
| S-05 | カート表示時およびチェックアウト開始時に、公開状態・購入権限・価格・在庫数を再検証する                                                                      | BR-CART-003, state-and-scenarios     |

| S-07 | カートはゲストと顧客のみ利用可能。operator / admin は利用不可                                                                                               | cart.md, roles-and-permissions       |

### UNKNOWN（仕様上の空白・矛盾）

UNKNOWN の詳細分類は `02-question-analysis.md`（Q-01〜Q-16）で扱います。主なものは次のとおりです。

- 再検証時の既存数量の扱い（Q-01）
- 数量入力の異常値（Q-02）
- 価格変更の承認操作（Q-03）
- カートのバージョン競合（Q-04）
- 合計金額の定義（Q-05）
- 追加時価格の表示要否（cart.md と補助文書が不一致）（Q-07）
- 補助文書の正本性（Q-15）

## 3. 停止条件の確認

- 対象範囲（カートの追加・数量変更・削除・再検証・統合・表示）は特定できている。
- 現在有効な仕様根拠（cart.md ほか正式正本）は解決できている。
- 重大な競合は、補助文書と cart.md の表示項目・版数の規則の不一致のみ。これは Q-07 / Q-15 として分類し、正式仕様を上書きしない。
- 局所的な UNKNOWN はあるが、対象全体は停止しない。ブロッカーは影響する観点だけを止める（02参照）。

## 4. 観測上の制約

- カートバージョン・カートID・明細IDは顧客UIに出ない（S-14）。版数に関する期待は、画面ではなく状態確認（テストコントロール・DB等）でのみ観測できる。観測方法の確認は `test-target-inspection` の対象。
- 本分析では実対象UIを開いていない。画面の挙動は spec 資料（webp / 記述）のみに基づく。current UI の確認は未実施。
