## 1. テスト分析範囲

- 対象機能: カート（ゲスト・会員のカート操作、数量上限、ログイン時のゲストカート統合、表示時・チェックアウト開始時の再検証、画面状態 default / empty / invalid-items）
- 案件固有のテスト目的 / 重点: 数量と価格の誤りが注文・請求へ流れないこと、問題のある明細でチェックアウトへ進まないこと、統合で権限外・無効な商品が入らないこと
- テストレベル: システムテスト（既定）。`test-architecture-design` を実施していないため、別レベルの割当は未決定
- 環境制約: 画面は web-desktop と android（`empty` / `invalid-items` は web-desktop のみ、カタログ上の必須プラットフォーム）。テストデータとして在庫数・購入上限数を変えられる商品が必要
- 対象外:
  - 注文への変換（Order 作成）、チェックアウトセッションの詳細、決済（別機能: `checkout-and-payment.md` / `orders.md`）
  - 価格計算ロジック本体（pricing）。カートは「再検証で価格変更を検出する」まで
  - 管理画面
- ブロッカー: なし。局所保留は UNK 8件、承認待ち PA-01〜PA-13（`pending-approvals.md`）

### リスク評価の方式

案件固有のリスク評価方式は採用されていないため、汎用のマトリクスを使います（影響度 × 発生可能性）。

| 影響度 \ 発生可能性 | 高 | 中 | 低 |
| ------------------- | -- | -- | -- |
| 高                  | 高 | 高 | 中 |
| 中                  | 高 | 中 | 低 |
| 低                  | 中 | 低 | 低 |

判断信頼度: 仕様根拠が SPEC（正式仕様）なら「高」、保留事項に依存する場合は「低」と記録します。

## 8. 仕様上の注意（分析で確認した事項）

- `empty` 状態の関連オラクルが BR-CART-001 に紐付いています（C-09）。本分析では `empty` を独立した表示要求（TR-015）として扱います。
- 無効SKU（`cart.md` の統合除外に記載）が、表示時の「問題明細」として扱われるかは仕様にありません。BR-CART-003 の再検証項目（公開状態・購入権限・価格・在庫数）に無効SKUは含まれないため、表示時の扱いは保留とします。
- 「会員」「customer」「ユーザー」「顧客」の用語の揺れ（C-11）は、テスト上「有効な customer アカウント」を指すものとして扱います。
