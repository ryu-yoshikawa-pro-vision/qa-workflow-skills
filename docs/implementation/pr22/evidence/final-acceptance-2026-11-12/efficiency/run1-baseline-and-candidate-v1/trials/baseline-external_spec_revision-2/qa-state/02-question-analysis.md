## 質問一覧

### Q-001（ブロッカー・局所）— カートバージョンの増分規則と統合後の検証値（UNK-001）

- 内容: 操作（追加・更新・削除・統合・価格承認）ごとにカートおよび明細のバージョンがどう変わるか、統合後にどの値を期待するかが、正式仕様にない。
- 根拠: SRC-001 AC-CART-002 は「カートバージョンが仕様どおり一致すること」を要求する。増分規則は SUP-001（business_rules §3、非正式）にのみ、「変更操作ごとに親カートの version を更新」と記載。
- 影響範囲: 統合（AC-CART-002）の版検証条件、カート更新の版検証条件。その他の条件（数量上限、利用者、表示）は影響を受けない。
- 回答がない場合: 版値を期待結果に含む条件はブロック中。版値に依存しない統合結果（数量・除外理由・abandoned遷移）は継続。
- 仮定案: 無し（期待値を創作しない。`ASM` 化は承認後のみ）。
- 回答後の正規化先: 正式仕様（features/cart.md）へ DECISION 化、または仕様更新。SUP-001 の規則をそのまま採用しない。
- 再開先: `spec-analysis`（仕様モデル更新）→ `test-condition-design`（該当条件の期待結果）

### Q-002（ブロッカー・局所）— 画面上の版競合（古いバージョンでのカート更新）（UNK-002）

- 内容: 別タブや別端末で版が進んだ後、古い画面から数量変更・削除を行った場合の挙動（拒否、再読込、通知、受理のいずれか）が未定義。
- 根拠: 正式仕様はチェックアウト境界の版検知（SRC-003, SRC-004）のみ。カート画面での版の扱いは SUP-001 にのみ「更新・削除は版を要求」と記載。
- 影響範囲: 版競合の条件（TCN-012 の版競合CI）のみ。通常の上限・統合・表示は継続。
- 回答がない場合: 版競合条件はブロック中。二重実行防止（SPEC-011）の条件は継続。
- 回答後の正規化先: DECISION または仕様更新（features/cart.md のUI・振る舞い規約）。
- 再開先: `spec-analysis` → `test-condition-design`

### Q-003（要確認）— 承認で解決できる問題種別と承認手段（UNK-003）

- 内容: BR-CART-003 は「価格変更」に承認を要求するが、AC-CART-003 は在庫切れ・公開停止・ランク不足を含めて「承認または修正」を要求する。在庫切れ等を承認できるのか（例: 数量を受け入れて続行）、承認操作の画面・状態がどこにあるのかが未定義。
- 影響範囲: 承認系の条件（TCN-008, TCN-009）。修正・削除による解決は SPEC-007 で確定しているため継続。
- 回答がない場合: 承認操作の条件はブロック中。価格変更のゲート（承認前は進行不可）は SPEC-006 で継続可能。
- 回答後の正規化先: 正式仕様（BR-CART-003, UI 状態）。
- 再開先: `spec-analysis` → `test-target-inspection`（承認UIが存在する場合の実対象確認）→ `test-condition-design`

### Q-015（要確認・非ブロッカー）— AC-CART-001 の上限記述の同期漏れ（改版による）

- 内容: 改版後の BR-CART-001 は上限源を「50」とするが、AC-CART-001 本文は「在庫数、購入上限数、99の各境界値」と記述し、改版前の値が残っている。
- 根拠: `product/docs/spec/features/cart.md` の BR-CART-001（50、差分と一致）と AC-CART-001（99）。`change-process.md` は正式仕様 → BR/AC → テスト設計を同一変更単位で同期することを求める。
- 影響範囲: TR-001、TCN-001-CI02 の参照先（AC-CART-001）。上限判定の規則と数値 50 は BR-CART-001 と差分により継続。
- 回答がない場合: BR-CART-001（50）を正とし、AC-CART-001 を根拠とする期待結果は要再検証のまま保持する。
- 提案: AC-CART-001 の「99」を「50」へ揃える。誤記訂正として扱うか改版として扱うかは仕様責任者が判断する。
- 回答後の正規化先: 正式仕様（features/cart.md の AC-CART-001）。
- 再開先: `spec-analysis`（AC参照の確認）→ 影響する TR-001 / TCN-001-CI02 のみ確認。

## 仮定候補（提案のみ・承認待ち）

仮定は期待結果の根拠に使いません。使う場合は権限を持つ責任者の明示承認と、仮定の正本一覧への記録が必要です（`pending-approvals.md`）。

- ASM-P1（Q-004）: 在庫減少で既存数量が上限を超えた場合は、数量を保持し問題として表示する。
- ASM-P2（Q-008）: 統合の許容上限は BR-CART-001 の上限（在庫・購入上限・50の最小値）と同一である。
