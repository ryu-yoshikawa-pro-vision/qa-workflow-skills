# 04 テスト要求設計: カート（ゲスト・会員）

- 対象 / 実行範囲: `test-requirement-design` / テスト要求（何を検証・保証するか）
- 入力: `01-spec-analysis.md`、`02-question-analysis.md`（保留H-01〜H-09）、`03-test-analysis.md`（RISK-001〜009、重点、レベル=システム）
- 状態: 完了（有効TR）。保留に依存するTRは「ブロック中」として明示
- 決定論的runtime（`requirement_structure`）: 未実行

## 方針

- テスト要求は「何を検証・保証するか」だけを書く。条件・組合せ・手順・具体値は書かない（`test-condition-design`以降）。
- 期待挙動は仕様根拠（SPEC-CART-xxx）へ追跡する。保留の期待挙動は作らない。
- テストレベルはユーザー・案件の指定がないため既定のシステムテスト。

## 要求の整合性チェック（設計内）

- TR-CART-001（拒否・維持）と TR-CART-006（統合の超過は除外）は別の仕様根拠で、矛盾しない。両方を残す。
- TR-CART-005 の合計金額は、TR-CART-001 の数量と TR-CART-008 の現在価格から導かれる。個別に検証する要求として残す。
- ブロック中のTRは、解除されるまで期待結果を作らない。
