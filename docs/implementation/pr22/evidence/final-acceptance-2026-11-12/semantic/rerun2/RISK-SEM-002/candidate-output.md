# テスト分析

## テスト分析範囲

- 対象機能 / 変更: 注文履歴（認証済み利用者が自分の注文を確認する主要利用者経路）。変更情報の入力はないため、新規 / 変更の区別はせず、現在有効な仕様 SPEC-ORD-HISTORY-001 を対象として扱う。
- 案件固有のテスト目的 / 重点: 注文履歴をE2E自動化対象として選定する価値を技術非依存で判断するため、テスト分析側のプロダクトリスク・テスト重点・テストレベル・技法を整理する。E2E自動化価値の選定そのものは本Skillでは行わない（下記「ルーティング」参照）。
- テストレベル: システムテスト（依頼・案件コンテキストに別レベルの指定がなく、依頼も別レベルを要求していないため既定値）。
- 環境制約: 入力になし。
- 対象外: E2E自動化価値の選定と候補範囲の確定（`e2e-test-selection`の責務）、locator / fixture / Playwright設定 / 実装可否 / 実装コスト（`e2e-test-inspection`の責務）、テストケース設計。
- ブロッカー: テスト分析全体を止めるブロッカーはなし。表示項目・遷移の詳細は仕様未定義のため、確認事項として`question-analysis`へ渡す（下記「ルーティング」）。
- 対象 / 実行範囲: テスト分析

## 選択したテスト技法

| テスト技法              | 適用領域                                         | 選択理由                                                     | 関連プロダクトリスク / 現在有効な仕様根拠     | `test-condition-design`への着眼点                                  |
| ----------------------- | ------------------------------------------------ | ------------------------------------------------------------ | --------------------------------------------- | ------------------------------------------------------------------ |
| デシジョンテーブル      | 認証状態 × 注文の所有関係 → 表示 / 非表示 / 遷移 | 結果が複数条件の組合せで決まる構造のため                     | RISK-001 / SPEC-ORD-HISTORY-001「自分の注文」 | 条件は認証状態と所有関係。各組合せの期待結果は仕様確定後に確定する |
| 同値分割                | 注文件数（0件 / 1件 / 複数件）                   | 件数が表示処理の代表区分になりうるため                       | RISK-002 / SPEC-ORD-HISTORY-001               | 代表区分の選定。上限値は仕様に無いため境界値分析は選ばない         |
| シナリオ / ユースケース | 認証済み利用者の主要経路                         | 利用者の一連の操作として成立することを確認する必要があるため | RISK-002 / SPEC-ORD-HISTORY-001               | 主要経路の手順と観測点。E2E化の可否は`e2e-test-selection`へ委ねる  |

選ばなかった技法: 境界値分析（数値境界が仕様にない）、状態遷移（遷移仕様が未定義）、ランダム / メタモルフィック / 構文ベース（問題構造に合わない）。

## ルーティング / 次の担当

- E2E自動化対象選定（注文履歴の主要利用者経路）: `e2e-test-selection`へ渡す。入力は SPEC-ORD-HISTORY-001（承認済み・current）と本成果物のRISK-002・テスト重点。本Skillでは候補の選定・不選定を決めず、選定結果を複製しない。
- 表示項目・遷移の詳細、未認証時の挙動: `question-analysis`
- テスト要求設計: 上記の確認事項が解消された後に`test-requirement-design`へ渡す。
