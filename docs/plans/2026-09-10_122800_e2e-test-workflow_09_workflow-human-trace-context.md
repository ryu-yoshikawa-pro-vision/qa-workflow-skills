## `qa-workflow`の拡張

`qa-workflow`を14 Skillのオーケストレーターへ拡張します。

### 担当すること

- ユーザー要求から最終成果物を識別する
- 対象範囲を識別する
- 有効な既存成果物を再利用する
- 必要な最も早いSkillから開始する
- E2E実装 / 実行 / 分析 / 報告の要否を判断してルーティングする
- Skill + 対象単位の状態を管理する
- ブロック中でも継続可能範囲を進める
- 上流変更時に影響する下流だけ`要再検証`へする
- 最も早い責任Skillへ戻す
- ユーザー要求に対して完了判定する

### 担当しないこと

- E2E対象の具体的な技術判断
- locator選択
- Playwrightコード生成
- Playwright実行コマンドの具体化
- 原因分析
- 報告内容の再解釈

工程固有ロジックは各Skillへ置き、`qa-workflow`へ複製しません。

### 開始時の情報収集

ワークフロー開始時にすべてのE2E情報を要求しません。

最初に必要なのは原則として次です。

- ユーザーが求める最終成果物
- 対象範囲
- 利用可能な既存成果物

次は必要になる工程まで遅延できます。

- repo / branch / working tree → E2E実装前
- browser操作能力 → 実UI調査が必要な時点
- テスト環境URL → 実UI調査または実行が必要な時点
- ローカルPlaywright runtime → execution直前
- credentials / test user → 該当TCで必要な時点
- 副作用許可 → 該当操作の前

これによりテスト設計だけの依頼にPlaywright環境やURLを要求しません。

## 人間による確認とブロック

### AIが継続してよいもの

- repo・仕様資料の読み取り
- 非破壊な実UI調査
- 既存構造の確認
- 仕様根拠に基づくテスト設計
- ユーザー指定または確認済み範囲の局所的Playwright実装
- lint / typecheck / test discovery等の非破壊検証
- 明示された安全なテスト環境への許可済み実行
- 証拠に基づく原因分析
- 影響範囲を限定した再検証 / 再実行

### 該当範囲をブロックするもの

- 必要な実UI確認能力がない
- Playwright runtimeが利用できない
- テスト環境URLが必要だがない
- test user / credential取得経路がない
- 必要なデータ状態を作れない
- cleanup方法を確定できない
- deployment version不明が原因判定へ影響し、追加確認が必要
- 大きなE2E基盤設計判断が必要

他の独立したTC・成果物は可能な範囲で継続します。

### 人間の決定または明示許可が必要なもの

- 有効な仕様根拠同士が競合し期待結果を決められない
- productionまたはproductionの可能性がある環境で状態変更が必要
- 未許可のデータ削除
- 決済
- 外部通知 / メール送信
- 権限変更
- アカウントロックにつながる操作
- その他の不可逆操作
- 新しいcredential / 権限付与が必要
- Playwright導入に大きな構造判断が必要
- プロダクトコードの修正へ進む必要がある

一度案件コンテキスト等で明示的に許可済みの同一範囲について、毎回同じ確認を要求しません。

## 成果物と追跡性

QA設計からE2E化した場合は、概念上次を辿れるようにします。

```text
現在有効な仕様根拠
  ↓
テスト要求
  ↓
テスト条件
  ↓
カバレッジ項目
  ↓
詳細TC
  ↓
E2E実装または明示した扱い
  ↓
実行結果
  ↓
結果分析
  ↓
テスト結果報告
```

TCなしの既存E2Eまたはユーザーが明示したE2E対象から開始する場合は、TCを作るためだけに上流工程へ戻さず、次を辿れるようにします。

```text
ユーザーが明示したE2E対象 または E2E実装参照
  ↓
resolved primary TestCase
  ↓
実行結果
  ↓
必要なら結果分析
  ↓
必要ならテスト結果報告
```

プロダクトリスクは従来どおり深度・優先度の横断入力です。

新しい巨大な共通ID体系は作りません。TCが存在しない経路のためだけにTCまたはTC IDを生成しません。

対象repoに既存方式がなければ、TCあり経路では最低限次を辿れるようにします。

```text
TC ID
↔ E2E実装参照
   repo-relative path + title path
↔ 実行単位
   E2E実装参照 + project + repeatEachIndex等 + retry
↔ 分析結果
↔ 報告
```

TCなし経路では、`E2E実装参照 ↔ 実行単位 ↔ 分析結果 ↔ 報告`を最低限の追跡とします。

Playwright session固有の`TestCase.id`だけを長期追跡の唯一の正本にしません。

## 案件コンテキストの拡張

`skills/qa-workflow/assets/project-context-template.md`へ、必要な場合だけ記録するE2E情報を追加します。

候補項目:

- 対象repo / workspace
- テスト環境URL
- 主たる対象origin
- 許可された外部origin / 外部依存
- 対象ブラウザ / Playwright project
- 認証方法
- 認証情報の取得方法または環境変数名
- 利用可能なtest user / role
- テストデータ・状態準備方法
- 副作用の許可範囲と根拠
- cleanup制約
- 証跡の保存・共有制約
- テスト対象version / build ID等の確認方法
- ローカル実行上の既知制約

password、token、cookie、secret値そのものは記録しません。
