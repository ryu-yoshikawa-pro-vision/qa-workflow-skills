# PR本文の運用規則

PR本文はメモ帳や作業日誌ではありません。レビューする人が「何のためのPRか」「現時点でどこまで完了しているか」を把握できるように、**目的と最新の状態だけ**を記載します。対象はこのrepositoryのすべてのPRです。親PR・子PR・Draft PRも例外ではありません。

## 記載する内容

### 目的

- このPRが実現することと、担当範囲・統合先などの重要な境界を簡潔に示す。
- 詳細な仕様、実装手順、完了条件は正本のPlanや担当文書に置き、必要なリンクだけを示す。

### 現在の状態

- 実装・文書・統合のうち、実際に完了したものと未着手・作業中のものを区別する。
- 検証は現時点の結果を簡潔に示す。未実施、失敗、SKIP、blockedはPASSと区別する。
- レビュー判断に必要な未完了事項・依存関係・停止理由と、最新の検証報告へのリンクを示す。
- Draft・レビュー可能・統合待ちなど、PRの現在の状態を正しく記載する。PRがopenであることだけを「実装完了」の根拠にしない。

## 記載しない内容

- 日付ごとの進捗メモ、過去の試行結果、更新履歴、逐次的な作業報告。
- 実行したコマンド・ログ・attempt一覧、長大なテスト結果、commit単位の説明。
- Planの全文、詳細な手順、担当チェックリスト、既に古くなった状況説明。
- 同じ情報の繰り返しや、根拠のない完了宣言。

## 更新の仕方

- 状態が変わったら、古い記載へ追記するのではなく、**本文全体を最新の内容へ更新**する。過去の経緯を維持するために本文を肥大化させない。
- 作業上必要な詳細な証拠、実施コマンド、判定と理由は `docs/reports/`、担当文書、CI・テスト成果物などの適切な正本に保存する。履歴はcommit・レビューコメント・対応するIssueにも残せるが、PR本文へ複製しない。
- 未検証・未設定・外部依存がある場合は、その事実を現在の状態として残す。最新の未完了事項を短く書くために、完了条件自体を削除しない。
- 親子PRでは、子PRの担当内完了と親PRの横断統合・最終受入を混同しない。正本のowner／引継ぎ先はリンクで示す。

## PR本文の形式

```markdown
## 目的

（このPRの目的・担当範囲・必要な正本へのリンク）

## 現在の状態

- （現在の実装・文書・統合状況）
- （現時点の検証状況。未実施／失敗／blockedも明示）
- （レビュー判断に必要な残件・依存と最新の証拠へのリンク）
```

PR本文は現況の要約です。詳細な履歴と実装・検証契約を削除する指示ではありません。
