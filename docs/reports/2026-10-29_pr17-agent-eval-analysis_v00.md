### Model / reasoning / CLI

修正後の新規生成はCodex `spawn_agent(model="gpt-6-luna", reasoning_effort="max", fork_turns="none")`の起動記録に各設定を明示した。起動toolは各Agentを受理し、Agentの自己申告を設定証拠に使っていない。別モデルへのfallbackは指定していない。親Codex sessionのversion記録は`0.165.0`。固定Linux CLI `0.163.0`や別の`codex exec`プロセスは起動していない。CLI `0.163.0`の[config schema](https://raw.githubusercontent.com/openai/codex/rust-v0.163.0/codex-rs/core/config.schema.json)と[child-agent設定適用順](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/core/src/agent/child_config.rs)を一次資料で確認し、既定設定に依存せずspawnごとに上書きを明示した。global configは変更していない。

Codexの起動記録で確認できるのは選択されたmodel ID / reasoning effortまでで、provider側のserving build telemetryは公開されずbuild IDは未取得。親環境の`codex --version`はWindows npm shimを指し、Linux optional package不足で起動せず、別CLIによる確認はできなかった。今回のCodex session記録は`0.165.0`。元46件の正確なmodel ID/buildも記録されておらず、修正前後を同一モデル・厳密同一条件のA/B比較とは扱わない。

### 情報アクセスと独立性

評価用rootとagent-visible rootは0700、agent-visible fileは0600。各Agent groupへ割り当てたSkill package・case inputだけを配置し、`expected.json`、評価用Reference、rubric、grader、validator、他groupの結果は含めていない。ただしgroup内では複数Skillと複数case inputを同じAgentへ渡した。Agentは親と同じworkspace/sandbox権限も継承するため、未staging fileへのread denial、case間の情報非共有、expected/graderへの物理アクセス遮断を証明できない。file access auditもない。したがって全結果は実動作検証であり、正式な独立評価・同条件評価ではない。

## 3. 優先した3件

- **SPEC-OUT-001**: `SPEC-D007`のFAILは、Machine Entity関係のenum欄に説明文を入れたこと。正規Markdown欄の値は`補足`で、説明は別欄へ置く契約をSkill/templateに明記した。Machine Entity `content.relations`の文字列配列schemaとは区別し、graderのenumは広げていない。
- **QUESTION-OUT-002**: `仮定候補`表のheaderは5列、最初のデータ行は4セルで、共通parserが例外を送出した。typed `MarkdownTableParseError`とsection/row/列数のdiagnosticを追加。runnerは`OUTPUT-MD-TABLE-001`のcase FAILとして返し、batchの残りを続ける。escaped `|`、separator列不一致、正常表、batch継続をテストした。
- **REG-OUT-002**: Agent JSONの`source_executions`はlistだったが、validatorはmappingの`.get`を前提にし例外となった。正規data contractに沿うcontainer/value shape検証を追加し、`REG-D018`で不正shapeを明示FAILにした。list/dict/null/missing/scalarを空containerへ黙って置換せず、baseline/run/activityを含む回帰テストでsource execution・actual start・result finalization意味を維持した。
